## Why This Report Exists

Masa sells a compelling story: a decentralized network for AI training data where independent worker nodes scrape the open web and social platforms, prove what they collected, and get paid in MASA. The token is listed and buyable, and the marketing cites more than a million nodes and millions of proprietary data points.

Two questions decide whether that story is real. First, is there a genuine on chain network with on chain MASA incentives, or is this a Bittensor subnet wearing a token? Second, does the MASA token you can actually buy do anything inside that network? This report answers both by reading the shipped source in the three canonical repositories and by querying the live token contract, rather than trusting the docs.

The short answer: the data network is real, but it is a Bittensor subnet, the rewards are paid in Bittensor emissions and not in MASA, the standalone protocol that once carried the on chain incentive story is a testnet stub with rewards literally labeled "Coming Soon", the headline traction numbers do not describe network nodes, and the token itself has collapsed to dust and is being migrated to a different token on a different chain.

## The Foundation: two codebases, one abandoned, one on Bittensor

There are two distinct implementations, and conflating them is where most of the marketing sleight of hand happens.

`masa-oracle` is the Go implementation of the "Masa Protocol", the peer to peer network of Oracle Nodes and Worker Nodes that the README describes as an "open, permissionless marketplace for specialized AI training data and compute resources". Reading its wiring shows the entire staking and token layer is pinned to the Sepolia testnet, and the reward surface is unimplemented. This repository has not been touched since January 2025.

`subnet-42` is the Python implementation that is actually live. Its own README opens with "Subnet 42 (Gopher)" and states plainly that it is "the Bittensor miner/validator wrapper code (neurons) for Subnet 42". Its dependencies are `bittensor` and `fiber`. This is where real miners run, real scraping happens, and real emissions are paid, none of which involve the MASA token.

## Claim 2: "Stake and earn MASA network emissions and fees for the work you provide"

**CLAIM**
> "Earn network emissions and fees for the work you provide, generating a new revenue stream." and "MASA is earned by contributing data, compute, and validation to the network." (`masa-oracle/README.md` and Masa marketing)

**REALITY: FALSE.** In the live subnet, rewards are Bittensor emissions distributed by the chain when validators call `set_node_weights`. No MASA is emitted or transferred anywhere in the reward path. In the abandoned Go protocol, the rewards figure shown to a node operator is a hardcoded string "Coming Soon!". The MASA ERC20 itself has no mint function, so on chain MASA emission is not merely unimplemented, it is impossible on the deployed contract. A legacy incentivized testnet did once distribute a fixed 3,000,000 MASA pool to the top 256 miners, but that was a bounded, pre funded, off chain transfer from existing supply rather than a mint, and it has ended; it is not the live reward mechanism.

## Claim 3: "More than a million nodes" and headline traction

**CLAIM**
> Marketing cites "over 1.4 million unique users, 48,000 node operators, and 38 million proprietary data points" and "1M plus nodes" style network scale.

**REALITY: FALSE as applied to network nodes.** The live network is a Bittensor subnet, and Bittensor subnets expose a bounded set of neuron UIDs (near 256). The validator iterates a routing table of registered nodes and syncs the subnet metagraph; there is no code path for a million node network. The large figures describe legacy Masa app users and cumulative data points from the earlier testnet era, not concurrent worker nodes on the live subnet.

**EVIDENCE**
```python
# subnet-42/validator/scorer.py  (get_node_data)
self.validator.metagraph.sync_nodes()
nodes = self.validator.routing_table.get_all_addresses_with_hotkeys()
logger.info(f"Found {len(nodes)} nodes in the routing table")
# iterates the bounded Bittensor metagraph, not a million node fleet
```
Public subnet trackers and the project's own operators describe the live network as roughly 256 miners running TEE workers, consistent with a standard Bittensor subnet slot cap.

**IMPACT:** The traction narrative that supports the valuation conflates an app user count with a decentralized node count. A reader is led to believe the network has orders of magnitude more independent infrastructure than it does.

## Claim 4: "Cryptographically verified, provable data provenance"

**CLAIM**
> Data is "cryptographically verified" and provable, implying strong, ideally zero knowledge, provenance guarantees.

**REALITY: OVERSTATED.** Provenance is Intel SGX Trusted Execution Environment attestation, not zero knowledge. Miners must run a separate `tee-worker` on SGX hardware, and validators score miners from telemetry counters that the TEE worker self reports (for example `twitter_returned_tweets`). The scorer's own comments acknowledge that summing counters across sources would allow amplification, and the active source list is fetched from a centralized Masa API. There is no zero knowledge proof of scraped content anywhere in the repositories.

**EVIDENCE**
```python
# subnet-42/validator/scorer.py:32
self.api_url = os.getenv("MASA_TEE_API", "https://tee-api.masa.ai").rstrip("/")
```
```python
# subnet-42/validator/scorer.py  (aggregate_telemetry_stats_without_validation)
# "we avoid summing across multiple sources (which would allow amplification)"
```
```python
# subnet-42/validator/platform_config.py  emission weights over self reported counters
twitter        emission_weight=0.7   # twitter_returned_tweets, twitter_scrapes ...
twitter-apify  emission_weight=0.05
tiktok, reddit, linkedin, web  emission_weight=0.05 each
llm            emission_weight=0.0
```

**IMPACT:** "Cryptographically verified" is a TEE attestation claim, which is meaningful but weaker and more centralized than the zero knowledge framing implies. Scoring rests on counters the worker reports about itself, mitigated by TEE integrity and delta logic rather than by cryptographic proof of the underlying data.

## Claim 5: "Permissionless" participation

**CLAIM**
> Anyone can join and provide data in an "open, permissionless" manner.

**REALITY: OVERSTATED.** Bittensor registration is permissionless in the sense that a hotkey can burn to register, but to be scored on Subnet 42 a miner's TEE worker must be present in a Masa operated registry reached at `MASA_TEE_API`, and administrative operations on that registry require `MASA_TEE_API_KEY`. The validator also pulls the active worker version and active stat name from the same central endpoint. Masa therefore holds an off chain gate over who counts as a valid worker.

**EVIDENCE**
```python
# subnet-42/validator/node_manager.py:261
masa_tee_api     = os.getenv("MASA_TEE_API", "")
masa_tee_api_key = os.getenv("MASA_TEE_API_KEY", "")
# TEE workers are registered and removed via this central, API key protected service
```

**IMPACT:** The decentralization story has a centralized choke point. Validation of who is a legitimate data worker depends on a service controlled by the team, not on chain consensus.

## Centralization and Token Control

Token contract: the mainnet MASA at `0x890cdf3c...944A` is not a proxy (both EIP1967 implementation and admin slots are empty), so it is not upgradeable, and the bytecode exposes no `mint` or `pause` selectors. Supply is fixed at 21,000,000,000. The `owner` is a single externally owned account `0x5560b6...5feb` (its code is `0x`, so it is a plain key, not a multisig), but with no mint or pause path the practical power of that owner over holders is limited. On the token contract itself, centralization risk is low.

Network control: the meaningful centralization is operational, not in the token. The subnet's worker legitimacy is gated by the Masa TEE API and API key, the `masa-oracle` bootnodes are Masa operated `*.test.miners.masa.ai` hosts, and reward distribution follows validator weight setting on Bittensor, where the subnet owner and top stake validators dominate.

## Product Reality

The subnet is genuinely live. `subnet-42` is actively maintained (last commit 2026-03-03), runs on Bittensor as SN42, and really does drive TEE workers scraping X, TikTok, Reddit, LinkedIn, and the web, with X the dominant scored source at 70 percent of emissions. The team, now Gopher, reports paying products and revenue on top of this data. So this is not vaporware at the infrastructure layer.

The token, however, is a separate story. As of 2026-08-05 MASA trades as a collapsed micro cap, roughly a low six figure market capitalization with negligible daily volume, listed across venues such as Uniswap, Gate, and Bitget but with dust liquidity. Masa rebranded to Gopher in September 2025 and has announced a 1:1 migration from MASA to a new `GOAI` token on a separate Cosmos based chain. The specific ERC20 audited here is therefore a legacy asset being wound down, with no on chain utility in the live network during its remaining life.

## Positive Findings

- The live data subnet is real, actively developed, and technically coherent. It is a working Bittensor subnet with genuine multi platform scraping, delta based scoring, and TEE worker integrity, not a mockup.
- The MASA token contract is clean: fixed 21,000,000,000 supply, non upgradeable (no proxy slots set), and no `mint` or `pause` selectors in bytecode. There is no inflation or freeze rug vector in the contract itself.
- TEE attestation, while weaker than the zero knowledge framing, is a legitimate provenance mechanism and is actually integrated (miners and validators both run the `tee-worker`).
- The team ships and iterates in public, and the code is honest in places the marketing is not, for example the "Coming Soon" rewards string and the explicit `XXX` note that block validation is missing.

## Conclusion

Masa is a real product attached to a misleading token narrative. The decentralized data network exists, but it is Bittensor Subnet 42, and its rewards are Bittensor emissions, not MASA. The standalone "Masa Protocol" that once carried the on chain incentive and staking story is a Sepolia testnet stub with rewards labeled "Coming Soon" and a placeholder blockchain, abandoned since early 2025. The MASA token you can buy has no emission path (no mint), no role in the live reward flow, a headline traction story that counts app users as if they were nodes, and a provenance claim that resolves to TEE attestation over self reported counters gated by a centralized Masa API. On top of that, the audited token has collapsed to a micro cap and is being migrated to a different token on a different chain.

Because the token contract is non malicious and the underlying subnet is genuinely live, this is not a hard scam. But the whole project fails the central test of a token audit: the asset does not do what it is marketed to do, its flagship decentralization and traction claims are overstated or false, and it is being deprecated. Score 47/100, Flagged, MEDIUM risk.
