## Why This Report Exists

Pocket Network is one of the oldest DePIN projects in crypto, launched in 2020, and it markets itself as a decentralized RPC layer where independent node runners ("suppliers") serve blockchain relays and earn POKT. Two narratives about it are simultaneously in circulation and both need testing against code:

1. The bullish narrative: a genuinely decentralized, cryptographically proven relay network with real usage.
2. The bearish narrative inherited from its Morse era: a token that mints new POKT for every relay and is therefore structurally inflationary and dilutive.

Both narratives predate the **Shannon** upgrade, a full rewrite that moved Pocket from its bespoke Tendermint fork (`pocket-core`) to a Cosmos SDK chain (`poktroll`). This report reads the actual Shannon source, then confirms the live parameters directly from the mainnet chain, because the single most important fact about POKT, whether it still inflates, is not a code default but an onchain governance parameter. We queried it directly rather than trusting the whitepaper or the README.

## Claim 1: A Genuine Decentralized Relay Network with Suppliers and Validators

> CLAIM (pocket.network): a decentralized network where independent node operators stake POKT and serve blockchain relays, coordinated by onchain sessions, secured by a validator set.

**REALITY: CONFIRMED IN CODE.**

Suppliers (the node runners, formerly "servicers") are first class onchain actors. A supplier stakes POKT and registers one or more service configs, each with RPC endpoints, so the protocol knows which chains that node serves. Staking is permissionless: the only gate is a minimum stake, and there is no allowlist.

**EVIDENCE**
```go
// poktroll/x/supplier/keeper/msg_server_stake_supplier.go:74,81
Services:                make([]*sharedtypes.SupplierServiceConfig, 0),
...
for _, serviceConfig := range msg.Services {
    servicesUpdate := &sharedtypes.ServiceConfigUpdate{ ... }
    supplier.ServiceConfigHistory = append(supplier.ServiceConfigHistory, servicesUpdate)
}
```

The live minimum stakes (verified onchain, not code defaults) show a real economic barrier that is orders of magnitude higher than the localnet defaults shipped in the source:

```text
Live onchain params (block 866526):
  supplier    min_stake = 59,500 POKT   (code default in supplier/types/params.go:16 is 1 POKT)
  gateway     min_stake =  5,000 POKT   (code default in gateway/types/params.go:16 is 0.0001 POKT)
  application min_stake =  1,000 POKT, max_delegated_gateways = 7
```

Validators are the standard Cosmos SDK / CometBFT staking validator set (the app wires in `stakingtypes`, `govtypes`, `upgradetypes` in `app/app_config.go`), which is why block production and slashing at the consensus layer are inherited from battle tested Cosmos modules rather than reinvented.

**IMPACT:** The relay network is genuinely decentralized at the protocol layer. Anyone with the minimum stake can register as a supplier and serve relays. The caveat is not permissioning but concentration of demand routing, addressed in Claim 5.

## Claim 2: Probabilistic Proof of Relay (the Claim and Proof Mechanism) Is Actually Implemented

> CLAIM: node operators prove the relays they served using a cryptographic claim and proof scheme, and proofs are required probabilistically to keep the chain cheap while remaining secure.

**REALITY: CONFIRMED IN CODE.** This is the technical heart of Pocket and it is fully implemented, not hand waved.

A supplier accumulates served relays into a Sparse Merkle Sum Trie and submits its root as a **claim**. When a **proof** is required, the supplier must submit a `ClosestMerkleProof`: a merkle branch to the leaf nearest a pseudorandom path derived from a future block hash, which the supplier cannot predict when serving relays. The chain then verifies the app ring signature on the relay request, the supplier signature on the response, the relay mining difficulty, and the merkle proof against the claimed root.

**EVIDENCE (validation pipeline, documented in the source header)**
```go
// poktroll/x/proof/keeper/proof_validation.go:21-28
## Relay Signature validation
1. verify(relay.Req.Signature, appRing)
2. verify(relay.Res.Signature, supplier.pubKey)
## Relay Mining validation
1. verify(proof.path) is the expected path; pseudo-random variation using onchain data
2. verify(proof.ValueHash, expectedDifficulty); governance based
3. verify(claim.Root, proof.ClosestProof); verify the closest proof is correct
```
```go
// poktroll/x/proof/keeper/proof_validation.go:331-338  (path is forced to onchain entropy)
expectedProofPath := protocol.GetPathForProof(proofPathSeedBlockHash, sessionHeader.GetSessionId())
if !bytes.Equal(proof.Path, expectedProofPath) {
    return types.ErrProofInvalidProof.Wrapf("the path of the proof provided (%x) does not match ...", ...)
}
// :461  verifyClosestProof
valid, err := smt.VerifyClosestProof(proof, claimRootHash, protocol.NewSMTSpec())
```

The probabilistic requirement is real and parameterized. A proof is mandatory if the claim value crosses a threshold, otherwise it is required with a governed probability:

```go
// poktroll/x/proof/keeper/msg_server_submit_proof.go:273,299
if claimeduPOKT.Amount.GTE(proofParams.GetProofRequirementThreshold().Amount) {
    requirementReason = types.ProofRequirementReason_THRESHOLD   // large claims always proven
}
...
if proofRequirementSampleValue <= proofParams.GetProofRequestProbability() {
    requirementReason = types.ProofRequirementReason_PROBABILISTIC  // otherwise sampled
}
```

Live onchain values (not code defaults): `proof_request_probability = 0.001`, `proof_requirement_threshold = 10 POKT`. In other words, on mainnet today every claim worth 10 POKT or more is fully proven, and below that a random 0.1 percent are audited. The code defaults are more aggressive (0.25 probability, 20 POKT threshold in `proof/types/params.go:18,24`), which shows governance has tuned these live.

**IMPACT:** The probabilistic proof of relay claim is CONFIRMED. This is a genuine, non trivial cryptographic construction (merkle sum tries, ring signatures, commit reveal entropy), and it matches the whitepaper design.

## Claim 3: Staking and Slashing

> CLAIM: suppliers are economically bonded and are slashed if they fail to prove the work they claimed.

**REALITY: CONFIRMED IN CODE**, with one honest caveat: the slashing exists and is wired, but the live penalty parameter is currently set to a negligible value.

Every actor type has real stake and unstake message handlers (`msg_server_stake_supplier.go`, `msg_server_stake_gateway.go`, and the application module). Supplier slashing on a missing proof is implemented directly: when a claim that required a proof expires without one, the supplier's stake is reduced by the proof missing penalty and that amount is burned.

**EVIDENCE**
```go
// poktroll/x/tokenomics/keeper/settle_pending_claims.go:620-681  slashSupplierStake
slashingCoin := *proofParams.GetProofMissingPenalty()
...
remainingStakeCoin = slashedSupplierInitialStakeCoin.Sub(slashingCoin)  // reduce supplier stake
...
k.bankKeeper.SendCoinsFromModuleToModule(ctx, suppliertypes.ModuleName, tokenomicstypes.ModuleName, ...)
k.bankKeeper.BurnCoins(ctx, tokenomicstypes.ModuleName, cosmostypes.NewCoins(slashingCoin))  // burn it
```

The caveat is the live parameter. The source ships a strong default:
```go
// poktroll/x/proof/types/params.go:30
DefaultProofMissingPenalty = cosmostypes.NewCoin(pocket.DenomuPOKT, math.NewInt(320e6)) // 320 POKT
```
but the live mainnet value queried onchain is **`proof_missing_penalty = 1 uPOKT`** (that is 0.000001 POKT). So the mechanism is fully coded and callable, but the economic penalty is presently disabled in practice, likely a deliberate choice while relay volume and the probabilistic sampling ramp up post migration.

**IMPACT:** Staking is CONFIRMED and economically meaningful (59,500 POKT to be a supplier). Slashing is CONFIRMED in code but currently toothless by parameter. A reader should not assume suppliers face material slashing risk today; they do not, until the DAO raises `proof_missing_penalty`.

## Claim 4: Token Economics, Is POKT Inflationary?

> CLAIM (legacy, Morse): POKT is minted for every relay, so it is structurally inflationary.
> CLAIM (current, Shannon): POKT is now a usage based, mint equals burn, and even deflationary token.

**REALITY: The current Shannon claim is CONFIRMED IN CODE. The legacy "runaway inflation" description is now outdated for the live chain.** This is the most important and most misunderstood fact about POKT, so it is worth being precise.

Under Shannon there are two independent minting paths, both implemented as Token Logic Modules in `x/tokenomics/token_logic_module/`:

**Path A, burn equals mint (the base path).** When an application consumes relays, the settlement amount is burned from the application's staked balance, then an equal amount (scaled by a mint ratio) is minted and distributed to suppliers, validators, the source owner and the DAO. PIP 41 introduced the mint ratio so the network can mint strictly less than it burns, permanently removing the difference.

```go
// poktroll/x/tokenomics/token_logic_module/tlm_relay_burn_equals_mint.go:109-147
// PIP-41: The minted amount is settlementAmount * mint_ratio, enabling deflation.
// When mint_ratio < 1, fewer tokens are minted than burned, permanently removing tokens.
mintRatio := tlmbem.tlmCtx.TokenomicsParams.GetMintRatio()
...
mintAmount := math.NewIntFromBigInt(new(big.Int).Quo(mintAmountRat.Num(), mintAmountRat.Denom()))
...
deflationAmount := settlementAmount.Sub(mintAmount)  // this many uPOKT are burned net
```

**Path B, global mint inflation (an optional add on).** A separate TLM mints brand new POKT on top of settlement, scaled by a global inflation parameter. If that parameter is zero, the TLM does nothing.

```go
// poktroll/x/tokenomics/token_logic_module/tlm_global_mint.go:85-101
globalInflationPerClaim := tlmgm.tlmCtx.TokenomicsParams.GetGlobalInflationPerClaim()
if globalInflationPerClaim == 0 {
    tlmgm.logger.Warn("global inflation is set to zero. Skipping Global Mint TLM.")
    return cosmostypes.NewInt64Coin(pocket.DenomuPOKT, 0), nil
}
...
newMintCoin := CalculateGlobalPerClaimMintInflationFromSettlementAmount(settlementCoin, globalInflationPerClaimRat)
```

The whole question of "is POKT inflationary" therefore reduces to two live governance numbers. We queried them directly from mainnet:

```text
Live onchain tokenomics params (block 866526), decoded from ABCI:
  global_inflation_per_claim = 0.000001   (code default is 0.1 in tokenomics/types/params.go:21)
  mint_ratio                 = 0.975      (code default is 1.0 in tokenomics/types/params.go:51)
  dao_reward_address         = pokt1dr5jtqaaz4wk8wevl33e7vkxsjlphljnjhyq2l
  mint-equals-burn split: supplier 79%, proposer/validators 14%, DAO 4.5%, source owner 2.5%
```

Interpretation with precision:
- **Global inflation is effectively switched off.** The live value 0.000001 is one part per million, five orders of magnitude below the code default of 0.1. There is no meaningful new issuance beyond replacing burned tokens.
- **The base path is net deflationary.** `mint_ratio = 0.975` means for every 100 POKT an application burns to pay for relays, only 97.5 are reminted; 2.5 are destroyed forever. At current usage that is roughly a seven figure annual net burn.
- The DAO can reverse this at any time by raising either parameter through governance. So POKT is deflationary by policy, not by protocol constraint. There is no hard supply cap (max supply is uncapped).

**IMPACT:** The old "POKT prints for every relay" critique was accurate for Morse but is no longer true for the live Shannon chain. Anyone repeating it in 2026 is describing a deprecated network. The precise and fair statement is: POKT today is usage based, mint equals burn, and mildly deflationary, but its non inflationary status is a revocable governance setting rather than a coded guarantee.

## Claim 5: A Permissionless, Decentralized Gateway Layer

> CLAIM: under Shannon anyone can stake POKT and run a gateway; the gatekeeper role is removed.

**REALITY: OVERSTATED.** True in code, materially concentrated in practice.

At the protocol level the claim holds. Gateway registration is permissionless; the only requirement is the minimum stake, and there is no allowlist or foundation approval in the handler:

**EVIDENCE**
```go
// poktroll/x/gateway/keeper/msg_server_stake_gateway.go:88-90
minStake := k.GetParams(ctx).MinStake
if msg.Stake.Amount.LT(minStake.Amount) {
    err = types.ErrGatewayInvalidStake.Wrapf("gateway %q must stake at least %s", msg.Address, minStake)
}
```

The de facto reality is different. The gateway operator Grove (formerly Pocket Network Inc, the founding core development company) historically routed roughly three quarters of all relays, with Grove plus Nodies at about 99 percent of traffic (Messari, Q2 2024). Grove has since announced it is moving up the stack, and as of late 2025 its endpoint traffic migrated to `api.pocket.network`, an endpoint whose paid traffic the Pocket Network Foundation is sponsoring during the transition. So the concentration did not disperse across many independent gateways; it largely shifted from one company's portal to a Foundation sponsored successor endpoint. The exact current per gateway split is not published in a primary source and should be treated as uncertain, but the pattern is clear: de jure permissionless, de facto concentrated.

**IMPACT:** The gateway layer is open by code and closed by market structure. Investors and integrators should not read "permissionless" as "decentralized in practice." A small number of gateways still front most demand.

## Claim 6: Decentralized DAO Governance

> CLAIM: Pocket is governed by a decentralized DAO with onchain parameter control.

**REALITY: OVERSTATED.** The onchain machinery is genuine, but effective control is more centralized than "DAO" implies, and it holds the tokenomics dials.

The good part is real: module parameters and chain upgrades are authority gated to the standard Cosmos SDK governance module account, not to an EOA or a foundation multisig hardcoded in the app.

**EVIDENCE**
```go
// poktroll/x/tokenomics/keeper/msg_update_params.go:23  (same pattern in every module)
if msg.Authority != k.GetAuthority() {
    return nil, ...ErrInvalidSigner.Wrapf("invalid authority; expected %s, got %s", k.GetAuthority(), msg.Authority)
}
// poktroll/app/app_test.go:20-21  authority resolves to the gov module account:
authorityAddr := authtypes.NewModuleAddress(govtypes.ModuleName)
require.Equal(t, "pokt10d07y265gmmuvt4z0w9aw880jnsr700j8yv32t", authorityAddr.String())
// poktroll/app/app_config.go:290  "By default modules authority is the governance module."
```

The caveats that pull this to OVERSTATED:
1. The Pocket Network Foundation (PNF) is the executive that enacts approved proposals, and much off chain deliberation happens on the forum and Snapshot before onchain execution. This is a stewarded DAO, not pure onchain token voting.
2. The Foundation operates core infrastructure. The mainnet seed node we connected to is `pnf-seed-three`, and the canonical RPC and faucet run on Foundation and Grove infrastructure.
3. Governance holds the inflation switch. As Claim 4 showed, `global_inflation_per_claim` and `mint_ratio` are ordinary parameters the DAO can change. The current deflationary posture is a vote away from reversal.

**IMPACT:** Governance is real and onchain, which is a genuine strength versus admin key projects. But calling it a fully decentralized DAO overstates it: a Foundation executes, runs infrastructure, and controls the levers that determine whether POKT inflates.

## Positive Findings (Credited)

1. **The flagship cryptography is real.** Probabilistic proof of relay via Sparse Merkle Sum Tries, closest merkle proofs, ring signatures and block hash entropy is fully implemented and validated onchain (`x/proof/keeper/proof_validation.go`). This is hard engineering, and it is present.
2. **Live, actively maintained mainnet.** Continuous block production since 2025-03-28, dozens of committed onchain upgrade handlers, and a clean Cosmos SDK architecture with dedicated modules per network role.
3. **Tokenomics genuinely reformed.** The move from Morse era per relay minting to Shannon burn equals mint, plus a live and working PIP 41 deflationary mint ratio of 0.975, is confirmed both in code and in the live parameters. Few DePIN tokens can show net burn from real usage.
4. **Real product traction.** Hundreds of millions of relays per day across 60 plus chains with several thousand supplier nodes. The token is used natively to pay for and settle the core product, not settled in an unrelated asset.
5. **Permissionless staking with real economic barriers.** Supplier, gateway and application staking are open to anyone, with live minimum stakes (for example 59,500 POKT per supplier) far above the token defaults, indicating active governance tuning.
6. **Honest migration.** Morse was deprecated and Shannon fully assumed mainnet; the `x/migration` module implements the claim path for Morse holders to recover balances and stakes on Shannon.

## Conclusion

Pocket Network passes. Reading the actual Shannon source against the live chain, the core claims that matter, a decentralized relay network, cryptographic probabilistic proof of relay, real staking, and a reformed non inflationary token model, are CONFIRMED IN CODE and CONFIRMED ONCHAIN. This is a legitimate, technically serious, long running DePIN, and the single most repeated criticism of it, structural inflation, is now factually outdated: on mainnet today `global_inflation_per_claim` is effectively zero and `mint_ratio` is 0.975, meaning POKT currently burns more than it mints.

The score is held to 76 rather than higher for three sober reasons. First, decentralization is real in code but concentrated in practice: gateways are permissionless yet most demand still flows through Grove and a Foundation sponsored endpoint, and the Foundation runs seeds and RPC. Second, the non inflationary and deflationary posture is a revocable governance parameter, not a protocol guarantee, and the same governance can flip it. Third, as a token POKT is a microcap (roughly $14M) with thin liquidity concentrated on a single Korean exchange and a price roughly 99.8 percent below its all time high, which is an investment risk independent of the technology.

Overall risk is **MEDIUM**: the technology risk is low (the code does what it says), but the concentration, governance discretion over issuance, and market liquidity risks are real and material.
