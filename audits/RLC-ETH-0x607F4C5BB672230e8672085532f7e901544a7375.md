## Executive Summary

iExec RLC is a genuine fixed supply ERC20 whose onchain reality closely matches its public and marketing profile. ## 1. Project and Product Reality

The product is real and the code is genuinely live, not just a marketing page. The confidential computing stack (DataProtector, Web3Mail, Web3Telegram, iApp Generator, TEE workers) is documented at docs.iex.ec, published as maintained npm packages (iexec 9.0.1, @iexec/dataprotector 2.0.0 beta, @iexec/web3mail 2.0.1, all updated in 2026), and deployed on Arbitrum One. The GitHub org shows active development across the SDK (423 stars), worker, market api and explorer v2 with pushes in June and July 2026. The important nuance is that the classic worker pool compute marketplace ran on the Bellecour sidechain, which was officially sunset on July 2 2026, and the project has repositioned to programmable privacy and confidential DeFi on Ethereum and Arbitrum. So the specific worker pool marketplace as marketed is mid transition while the underlying TEE tooling is working today.

**Project level flags:** product repositioning (Bellecour sidechain sunset July 2026, users forced to migrate RLC); marketplace usage numbers not quantified publicly; roadmap language vague on dates

## 2. Website and Frontend Integrity

VERDICT: CLEAN | CONFIDENCE: high
The iex.ec homepage is a static Webflow marketing site and contains no Ethereum address of any kind in the HTML or in the three JavaScript bundles, so there is no exposure to an address swap, a lookalike substitution, or a clipboard hijack targeting the official RLC token contract. There is no wallet connect flow, no window.ethereum usage, and none of the drainer signatures such as approve, permit, transferFrom, setApprovalForAll, signTypedData, or eth_sendTransaction, meaning the user facing wallet surface is effectively zero. All scripts load from trusted first party or vendor hosts (Webflow CDN, Cloudfront jQuery, Google webfont, Cloudflare) with no obfuscation, no eval or atob or base64 decoding, and no remotely injected untrusted code. The page shows no live metrics, price, or TVL figures and displays no audit or certification badges, so there are no unbacked statistics or fake trust claims to reconcile. Overall the marketing content and the underlying code are consistent and benign, with the only cosmetic note being that the bundle filenames carry a staging label.

## 3. Traction and Claims

Traction is partly verifiable and partly opaque. RLC itself is easy to verify: it is a well established token (ICO era 2017) with market cap near 22.7 million USD, roughly 2.9 million USD daily volume, and canonical contracts on Ethereum (0x607f4c5bb672230e8672085532f7e901544a7375) and Arbitrum (0xe649e6a1f2afc63ca268c2363691cecaf75cf47c) that can be inspected onchain. What is not verifiable from public sources is the operational scale: iExec does not publish headline counts of tasks executed, deals settled, or active workers, and the explorer at explorer.iex.ec is a client side app rather than a stats dashboard, while historical Bellecour data is being wound down. Named users and integrators such as Aethir, Ar.io, Bond, ApeBond and Otomato appear real but are presented without hard usage figures.

## 4. Token Utility and Economics

RLC has genuine protocol utility rather than being purely speculative. The PoCo layer requires RLC to be locked (staked as sRLC) during a task, distributes payment in RLC to the app provider, protected data provider and worker, and uses staked deposits as economic security for correct execution. On Arbitrum every confidential transaction and tool interaction is designed to route demand through RLC. The caveat is that real usage volume is modest, so utility is real and enforced by contract but not yet at large scale.

The current iex.ec site leads with confidential computing and privacy messaging and treats RLC mostly as a linked topic rather than a marketing centerpiece. Public and documentation sources describe RLC as the native token that pays for compute and is staked by workers, and they state that the supply is written in stone with no admin access. Onchain data supports the no inflation part because there is no mint function, though strictly speaking the token still carries a nonzero owner set to the old crowdsale contract. That owner cannot mint, pause, or refreeze transfers, so the practical meaning of the claim holds. Overall the marketing and public claims are honest about supply and utility.

---

## 5. Claim versus Reality

- "There is no admin access to the RLC ERC20 smart contract, meaning the total supply is written in stone, and can never change" / Reality: onchain confirms there is no mint function so supply cannot rise, yet the token still exposes a nonzero Ownable owner, so the wording is slightly loose although that owner has no power to mint, pause, or refreeze transfers.
- iExec markets RLC as the native token of a decentralized confidential computing marketplace with "composable, auditable, and governable privacy" / Reality: onchain RLC is a plain fixed supply ERC20 with no compute or privacy logic, since that logic lives in separate PoCo protocol contracts, consistent with RLC being purely a payment and staking utility token.
- Public sources cite an OpenZeppelin audit that found no severe security problems / Reality: this matches the onchain bytecode, which is a simple StandardToken with no proxy, no pause, and no mint surface.

## 6. Contract Security Check (supporting)

- Total supply is about 86,999,785 RLC (raw 86999784986845492, 9 decimals) and the bytecode contains no mint function, so supply is fixed and cannot inflate; public trackers put circulating near 72.4M with total as the effective max.
- Owner is a contract at 0xec33fb8d7c781f6feaf2dd46d521d4f292320200 (the 2017 crowdsale, itself owned by 0x9ed07b5db7dad3c9a0baa3e320e68ce779063249); this owner cannot mint or pause and its only token power was unlock, which is already spent.
- No emission or minting mechanism exists; all tokens were created at deployment in 2017 and the token is not mineable, so there are no ongoing unlocks or new issuance.
- Not a proxy (EIP1967 implementation and admin storage slots are empty), not upgradeable, not pausable, no fee on transfer, decimals 9, and locked() returns false with no relock function so transfers are permanently enabled.

Reading the contract live on a public Ethereum RPC confirms name iEx.ec Network Token, symbol RLC, and 9 decimals at 0x607F4C5BB672230e8672085532f7e901544a7375, which is the exact address supplied for review. Total supply is 86999784986845492 base units, about 86,999,785 RLC, and the bytecode exposes transfer, burn, owner, transferOwnership, and unlock but no mint, no pause, and no proxy slots. The owner is the 2017 crowdsale contract 0xec33fb8d7c781f6feaf2dd46d521d4f292320200, which cannot create new tokens. The locked flag reads false and no relock function exists, so transfers are permanently enabled. There is no fee on transfer, making this a clean fixed supply StandardToken.
