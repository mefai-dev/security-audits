## Why This Report Exists

Most reports we publish document projects whose code contradicts their marketing. Numerai is the opposite kind of subject: a hedge fund and data science tournament that has shipped working Ethereum contracts since 2017 and, unusually, voluntarily gave up its own control over the token in 2019. The purpose here is the same discipline applied fairly. We read the actual public source, claim by claim, credit what is genuinely implemented, and flag where a reader might over read the words "decentralized" or "trustless" into what is in fact an honestly hybrid design.

We are not making accusations. We are not spreading FUD. We read the source and show what is actually implemented. Numerai earns real credit on this pass. NMR is a genuine fixed supply ERC20 with minting permanently disabled in code, the staking is real on chain locking of a user's own NMR, and the burns are real irreversible destruction of NMR. The single honest caveat is that the tournament scoring, and therefore the decision of how much NMR to burn or release, is computed off chain by Numerai and enforced by a privileged operator key, not by any on chain scoring logic. Numerai does not hide this, which is why the caveats below are graded Medium and Low rather than Critical.

## Method

For every major token or protocol claim we located the relevant code in the real repositories (erasureprotocol/NMR for the token, numerai/tournament-contracts for the tournament and staking integration, erasureprotocol/erasure-protocol for the Erasure staking and griefing primitives), fetched raw files from GitHub, and read what is actually implemented. Each claim is labelled CONFIRMED IN CODE, OVERSTATED, or FALSE, with a repository path, file, line context, and a short verbatim snippet. On chain facts (fixed 11,000,000 supply, minting disabled) were corroborated against Numerai's own NMR 2.0 upgrade record and public token data.

## The Foundation: NMR Was Once Centrally Minted, Then Frozen on Purpose

**CLAIM:**
> NMR is a fixed capped ERC20.

**REALITY:** CONFIRMED IN CODE, but only true from July 2019 onward. The honest history matters. NMR launched in 2017 as an upgradeable proxy (NumeraireBackend) that delegated all logic to a swappable delegate contract. The original delegate let Numerai mint new NMR on a weekly disbursement schedule up to a 21,000,000 hard cap, and let a Numerai multisig move and destroy tokens. In July 2019 Numerai deployed NumeraireDelegateV3, pointed the proxy at it, and then called disableContractUpgradability, which permanently repurposed mint() into a burn and removed Numerai's ability to ever change the logic again.

**EVIDENCE:**
```solidity
// erasureprotocol/NMR  contracts/NumeraireShared.sol
uint256 public supply_cap = 21000000e18;            // original 21M cap
uint256 public weekly_disbursement = 96153846153846153846153;
// getMintable() = initial_disbursement + weekly_disbursement * weeks_elapsed - total_minted
```
```solidity
// erasureprotocol/NMR  contracts/NumeraireDelegate.sol  (original, pre 2019)
function mint(uint256 _value) onlyOwner returns (bool ok) {
    require(safeAdd(total_minted, _value) <= supply_cap);   // could still create tokens
    require(_value <= getMintable());
    balanceOf[numerai] = safeAdd(balanceOf[numerai], _value);
    totalSupply = safeAdd(totalSupply, _value);
    total_minted = safeAdd(total_minted, _value);
}
```
```solidity
// erasureprotocol/NMR  contracts/NumeraireBackend.sol:31-33
function disableContractUpgradability() onlyManyOwners(sha3(msg.data)) {
    contractUpgradable = false;        // one way, removes the ability to swap the delegate
}
```
Numerai's own NMR 2.0 record states it plainly: "Maximum supply is reduced from 21 million to 11 million," "all 11 million of the tokens have now been minted. There will never again be minting of the token," and "NMR smart contract is no longer controlled or upgradeable by Numerai."

**IMPACT:** The "fixed capped" property is real and now immutable, but it was a deliberate 2019 decision, not an original property. The code constant supply_cap still reads 21000000e18; the effective 11,000,000 cap is enforced not by that number but by the permanent disabling of the mint path (Claim 1). A reader should understand the fixed supply as "Numerai gave up minting," not "minting was never possible." Informational.

## Claim 1: NMR is a fixed capped ERC20 with minting permanently disabled

**CLAIM:**
> NMR is a fixed, capped ERC20. Numerai can no longer mint NMR. All NMR that will ever exist exists today.

**REALITY:** CONFIRMED IN CODE. In the live V3 delegate the mint() entry point does not create tokens. It burns the caller's own balance. There is no reachable code path anywhere in the deployed contract that increases totalSupply. Because upgradability was permanently disabled, no future delegate can reintroduce minting. Supply can only ever go down through burns.

**EVIDENCE:**
```solidity
// erasureprotocol/NMR  contracts/NumeraireDelegateV3.sol:10-14 (header comment)
// Delegate V3: 1) Disabled upgradability  2) Repurposed burn functions
//              3) User NMR balance management through the relay contract

// NumeraireDelegateV3.sol:113-116  -- mint() now BURNS, it cannot create tokens
function mint(uint256 _value) public returns (bool ok) {
    _burn(msg.sender, _value);
    return true;
}
// NumeraireDelegateV3.sol:127-133
function _burn(address _account, uint256 _value) internal {
    require(_account != address(0));
    totalSupply = totalSupply.sub(_value);
    balanceOf[_account] = balanceOf[_account].sub(_value);
    emit Transfer(_account, address(0), _value);
}
```
```solidity
// NumeraireBackend.sol:17-19  standard ERC20 metadata
string  public name     = "Numeraire";
string  public symbol   = "NMR";
uint256 public decimals = 18;
```

**IMPACT:** Positive and verifiable. NMR is a genuine fixed supply asset, 11,000,000 minted with the live total supply now about 10,625,915 and only decreasing through burns, minting is impossible, and the property is locked by the one way disableContractUpgradability call. This is the strongest confirmation in the report and it is independently checkable on chain. Informational.

## Claim 2: NMR is burned for bad predictions

**CLAIM:**
> When a data scientist's staked model performs badly, their staked NMR is burned. Burning is a real, irreversible destruction of tokens.

**REALITY:** CONFIRMED IN CODE. Both the direct tournament path and the Erasure path perform a real burn that reduces totalSupply and sends value to the zero address. The mechanism is unusual (the burn is implemented by calling the repurposed mint() and numeraiTransfer() functions rather than a conventional burn), but the effect is genuine destruction, not a transfer to a treasury.

**EVIDENCE:**
```solidity
// numerai/tournament-contracts  contracts/NumeraiTournamentV3.sol:471-477
function _burn(uint256 _value) internal {
    if (INMR(_TOKEN).contractUpgradable()) {
        require(INMR(_TOKEN).transfer(address(0), _value));   // pre V3 path
    } else {
        require(INMR(_TOKEN).mint(_value), "burn not successful");  // V3: mint() burns
    }
}
```
```solidity
// erasureprotocol/erasure-protocol  contracts/modules/BurnNMR.sol:14,19-21
address private constant _NMRToken = address(0x1776e1F26f98b1A5dF9cD347953a26dd3Cb46671);
function _burn(uint256 value) internal {
    require(iNMR(_NMRToken).mint(value), "nmr burn failed");  // destroys tokens
}
```
```solidity
// erasure-protocol  contracts/modules/Staking.sol:68-78
function _burnStake(TokenManager.Tokens tokenID, address staker, uint256 amountToBurn)
    internal returns (uint256 newStake) {
    uint256 newDeposit = Deposit._decreaseDeposit(tokenID, staker, amountToBurn);
    TokenManager._burn(tokenID, amountToBurn);     // -> BurnNMR._burn for NMR
    emit StakeBurned(tokenID, staker, amountToBurn);
}
```

**IMPACT:** Positive. "NMR is burned for bad predictions" is literally true at the level of token mechanics. The burned NMR is gone forever and the total supply drops. This is a real deflationary slashing primitive, not marketing. Informational.

## Claim 3: Data scientists stake NMR on chain

**CLAIM:**
> Data scientists stake NMR on their predictions. Staking is putting real NMR at risk.

**REALITY:** CONFIRMED IN CODE. Staking is a genuine on chain lock of the user's own NMR. In the tournament contract the public stake() path has the user move their own tokens; in the Erasure agreements the stake is an actual ERC20 deposit into the agreement contract. The staked NMR really leaves the user's control and is really at risk of the burn in Claim 2.

**EVIDENCE:**
```solidity
// numerai/tournament-contracts  contracts/NumeraiTournamentV3.sol:270-281
function stake(uint256 tournamentID, uint256 roundID, bytes32 tag,
               uint256 stakeAmount, uint256 confidence) public whenNotPaused {
    // user-initiated; the caller's own NMR is pulled via transferFrom
}
```
```solidity
// erasure-protocol  contracts/modules/Staking.sol:24-32
function _addStake(TokenManager.Tokens tokenID, address staker, address funder,
                   uint256 amountToAdd) internal returns (uint256 newStake) {
    newStake = Deposit._increaseDeposit(tokenID, staker, amountToAdd);
    TokenManager._transferFrom(tokenID, funder, address(this), amountToAdd);  // real deposit
}
```
```solidity
// erasure-protocol  contracts/agreements/CountdownGriefing.sol:111-125
function increaseStake(uint256 amountToAdd) public {
    require(isStaker(msg.sender) || Operated.isOperator(msg.sender), "only staker or operator");
    Staking._addStake(Griefing.getTokenID(staker), staker, msg.sender, amountToAdd);
}
```

**IMPACT:** Positive. The stake is real capital at real risk on Ethereum, exactly as marketed. Informational.

## Claim 4: The staking and slashing is a decentralized, trustless mechanism

**CLAIM:**
> The tournament mechanism is decentralized and trustless. Stakes and burns are enforced by smart contracts.

**REALITY:** OVERSTATED. The burn is real (Claim 2), but the decision of whether to burn and how much is not trustless. In the tournament contract, resolveStake, which sets the burn amount, is gated by onlyManagerOrOwner, a single Numerai controlled role. In the Erasure agreement, punishment is gated to the counterparty or operator, and in Numerai's deployment Numerai is that operator. There is no on chain scoring, dispute, or challenge process that constrains the burn amount. A staker cannot contest the number the operator supplies.

**EVIDENCE:**
```solidity
// numerai/tournament-contracts  contracts/NumeraiTournamentV3.sol:305-350
function resolveStake(uint256 tournamentID, uint256 roundID, address staker,
                      bytes32 tag, uint256 burnAmount)
    public onlyManagerOrOwner whenNotPaused onlyUint128(burnAmount) {
    // Numerai alone chooses burnAmount and when the stake resolves
}
```
```solidity
// numerai/tournament-contracts  contracts/NumeraiErasureV1.sol
// createStake / increaseStake / releaseStake / resolveAndReleaseStake / punish / reward
// EVERY state changing entry point carries: onlyManagerOrOwner, whenNotPaused
```
```solidity
// erasure-protocol  contracts/agreements/CountdownGriefing.sol:150-166
function punish(uint256 punishment, bytes memory message) public returns (uint256 cost) {
    require(isCounterparty(msg.sender) || Operated.isOperator(msg.sender),
            "only counterparty or operator");
    return Griefing._grief(msg.sender, _data.staker, punishment, message);
}
```

**IMPACT:** The enforcement of the outcome is centralized in a Numerai operator key, and the contracts are pausable by Numerai (whenNotPaused). The contracts guarantee that a stake exists and that a burn, once ordered, is real and irreversible. They do not guarantee that the burn amount is fair or correctly derived from performance. The honest description is "on chain settlement of an off chain decision," not "trustless enforcement." Medium.

## Claim 5: The tournament is enforced on chain by the smart contract

**CLAIM:**
> A real hedge fund tournament where predictions are scored and NMR is burned for bad predictions, enforced by the blockchain.

**REALITY:** OVERSTATED. The scoring is entirely off chain. The blockchain never sees a prediction, a target, a correlation, or a performance score. Numerai computes model performance on its own servers against held out market data, then submits only the resulting burn or release amount as a privileged transaction. The smart contract is a settlement and custody layer, not a scoring engine. Numerai is honest about this in its documentation, so this is an overstatement of the word "enforced," not a fabrication.

**EVIDENCE:**
```solidity
// numerai/tournament-contracts  contracts/NumeraiTournamentV3.sol
// The contract stores stakeAmount / confidence and, on resolveStake, applies a
// burnAmount that is an INPUT supplied by onlyManagerOrOwner. There is no
// scoring, ranking, correlation, or performance computation anywhere on chain.
```
```solidity
// NumeraiTournamentV3.sol:239-266  Numerai-side custody and movement
function stakeOnBehalf(...) public onlyManagerOrOwner whenNotPaused { ... }   // stakes custodied NMR
function withdraw(address from, address to, uint256 value)
    public onlyManagerOrOwner whenNotPaused { IRelay(_RELAY).withdraw(from, to, value); }
```

**IMPACT:** The intelligence of the tournament, the scoring that decides winners and losers, lives on Numerai's centralized off chain infrastructure. The chain provides transparency and finality for the money movements (stake, burn, release) but not for the judgment that drives them. This is a legitimate and openly disclosed hybrid architecture, but present tense claims that the tournament is "enforced by the blockchain" overstate what the contracts do. Medium.

## Claim 6: Staking NMR is non custodial

**CLAIM:**
> Users stake their own NMR and remain in control of their tokens.

**REALITY:** OVERSTATED for the operational path. The token itself is fully non custodial (Claim 1, an ERC20 in the user's wallet). But the tournament staking flow includes a Numerai operated Relay through which Numerai can move NMR on behalf of custodied accounts. stakeOnBehalf pulls NMR from a Relay custodied balance, and withdraw lets the manager move NMR between addresses through the Relay. In practice much of Numerai's staking accounting has run through Numerai held balances with only net burns and releases settled on chain.

**EVIDENCE:**
```solidity
// numerai/tournament-contracts  contracts/NumeraiTournamentV3.sol:257-266
function withdraw(address from, address to, uint256 value)
    public onlyManagerOrOwner whenNotPaused {
    IRelay(_RELAY).withdraw(from, to, value);      // manager moves NMR via the Relay
}
// contracts/Relay.sol grants the tournament contract authority to withdraw
// NMR from accounts that approved the Relay
```

**IMPACT:** Holding NMR is non custodial. Participating in the tournament through the Relay flow involves a trust relationship with Numerai over the staked balance. Users who stake by directly locking their own tokens keep the non custodial property; users whose balances sit behind the Relay do not. Low.

## Additional Note: The burn is implemented through a non standard token hack

Worth stating because integrators repeatedly trip on it. NMR has no conventional burn function. Burning is done by calling mint(value), which V3 repurposed to subtract from the caller's balance, and burnFrom is done by calling numeraiTransfer(from, value). The Erasure BurnNMR module documents this explicitly as a "non standard implementation of the NMR burn functions."

**EVIDENCE:**
```solidity
// erasure-protocol  contracts/modules/BurnNMR.sol:25-27
function _burnFrom(address from, uint256 value) internal {
    require(iNMR(_NMRToken).numeraiTransfer(from, value), "nmr burnFrom failed");
}
```

**IMPACT:** No security flaw, but any third party integrating NMR must special case it. A naive integration expecting a standard burn/burnFrom will fail. Informational.

## Conclusion

Numerai is a genuine project whose token and staking code substantially deliver what it claims, and it is a rare case of a team that voluntarily surrendered its own power over the token. NMR is a real fixed supply ERC20 with minting permanently and immutably disabled in code (Claim 1). Burning NMR for bad predictions is real irreversible destruction of supply, on both the tournament path and the Erasure path (Claim 2). Staking is a real on chain lock of the user's own NMR at genuine risk (Claim 3). Three load bearing claims are confirmed in code and none are false.

The overstatements are the familiar gap between "decentralized and trustless" language and a design that is honestly hybrid. The tournament scoring is computed off chain by Numerai (Claim 5), the burn and release amounts are decided by a single Numerai operator key and cannot be contested on chain (Claim 4), and the Relay based staking flow introduces a custodial relationship over staked balances (Claim 6). None of this is concealed. Numerai's own communications describe the off chain scoring and the 2019 handover of token control. The score is high precisely because the token claims are fully verifiable and immutable on chain, and the caveats are centralization of judgment rather than any broken or dishonest code.

Score 86 out of 100, LOW RISK, driven entirely by the centralization of scoring and slashing judgment, not by any broken, hidden, or dishonest code.
