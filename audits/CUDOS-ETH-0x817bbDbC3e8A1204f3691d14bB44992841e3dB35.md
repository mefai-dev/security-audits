## Why This Report Exists

Cudos markets itself as a decentralized compute DePIN: a network where idle machines are rented out and where the CUDOS token settles and secures the work. The project also ran its own sovereign Cosmos SDK chain. In 2024 Cudos joined the Artificial Superintelligence Alliance, and CUDOS holders are now directed to convert to FET. A buyer looking at the live ERC20 today needs to know three things that marketing pages blur together: whether the compute marketplace is actually decentralized and settled on chain, whether the Cosmos chain is still alive, and whether the token has any standalone utility left after the merger. This report tests each against the real source and the real chain state, and states plainly that the chain and the standalone token are being deprecated.

## Method

Read only, public sources. On chain facts were pulled with raw `eth_call` and `eth_getCode` against two independent Ethereum RPC providers and cross checked. The deployed bytecode was disassembled to enumerate function selectors, which were resolved against the 4byte directory and matched to the verified Solidity source. The Ethereum token, the Ethereum staking system, and the `cudos-node` chain were cloned from `github.com/CudoVentures` and read directly, including the module registration in `app/app.go`, the `x/` module tree, and the `cudoMint` minting logic. The compute product was verified by reading the official `cudo-compute-python-client`, whose base URL and operations reveal a conventional cloud API rather than a blockchain. No team, identity, or private data was assessed.

## The Foundation: a real cloud business, a real but now stopped chain, and a token migrating away

Three separate artifacts sit under the "Cudos" name, and the audit only makes sense once they are separated.

First, an Ethereum ERC20 (`cudos-eth-token-contract`), a clean fixed supply OpenZeppelin token. Second, a sovereign Cosmos SDK chain (`cudos-node`) with its own native coin `acudos`, real Tendermint validators, staking, governance, an Ethereum gravity bridge, and CosmWasm. Third, Cudo Compute (`cudo-compute-python-client`, `terraform-provider-cudo`), a centralized cloud that provisions virtual machines and GPUs through a REST API.

The single most important fact for a present tense reader is stated by the project itself at the top of the chain repository:

```
cudos-node/readme.md:1
The CUDOS Network merged into ASI on October 28, 2024 and as a result the CUDOS blockchain is not running anymore. For more information please visit the merger section of the docs.
```

The repository is archived (GitHub `archived: true`, last push 2026-03-27, created 2021-03-30). The chain is off. What remains live is the Ethereum ERC20, which is now a vehicle for migrating to FET.

## Claim 1: "CUDOS is a live token with a fixed, verifiable supply"

CLAIM: A fixed ten billion CUDOS supply, mintable only once at genesis, on a standard non upgradeable ERC20.

REALITY: CONFIRMED IN CODE and confirmed on chain. The live contract matches the published source exactly. Supply is minted once in the constructor, there is no mint path afterward, the contract is not a proxy, and there is no owner or pause. The only special behavior is a one time transfer unlock, which has already been flipped on, so the token moves freely.

EVIDENCE:

```
cudos-eth-token-contract/contracts/CudosToken.sol:8,14,17,24-28
contract CudosToken is ERC20("CudosToken", "CUDOS") {
    bool public transfersEnabled = false;
    uint256 constant internal TEN_BILLION = 10_000_000_000;
    constructor (CudosAccessControls _accessControls, address _initialSupplyRecipient) public {
        require(_initialSupplyRecipient != address(0), "CudosToken: Invalid recipient of the initial supply");
        accessControls = _accessControls;
        _mint(_initialSupplyRecipient, TEN_BILLION * (10 ** uint256(decimals())));
    }
```

On chain confirmation (raw RPC results): `totalSupply()` = `0x204fce5e3e25026110000000` = 10,000,000,000e18; `decimals()` = `0x12` = 18; `transfersEnabled()` = `0x...01` = true. Selector scan of `eth_getCode` shows the standard ERC20 set plus `transfersEnabled/toggleTransfers/updateAccessControls/accessControls/withdrawStuckEther` and no `mint`, no `owner`, no `pause`, no proxy `implementation`.

IMPACT: Positive for token integrity. There is no hidden inflation, no upgrade backdoor, and no honeypot style transfer trap in the live state. Contract risk is low.

## Claim 2: "A genuine decentralized compute marketplace"

CLAIM: Cudos is a decentralized network that pools idle computing power from independent providers into a permissionless marketplace.

REALITY: OVERSTATED. The delivered product, Cudo Compute, is a conventional centralized cloud. Its own SDK states that every operation is an HTTP call to a single company hosted REST API, and the operations are the classic cloud control plane: create and terminate virtual machines, attach disks, manage networks and security groups, open billing accounts, add credit, and generate API keys. Users pay a billing account, not a token, and Cudo curates the data centers. Distributed data centers are not the same thing as a decentralized, permissionless, tokenized marketplace.

EVIDENCE:

```
cudo-compute-python-client/README.md
All URIs are relative to https://rest.compute.cudo.org
Operations include: Create virtual machine, Start, Stop, Reboot, Terminate,
Create storage disk, Create network, Create security group,
Create billing account, Add credit to billing account, Generate API key,
List machine types, List GPU models, List data centers, Get host count
```

IMPACT: The DePIN framing is marketing over a centralized cloud. The token is not required to buy compute, and provider onboarding is company gated, so the "decentralized marketplace" descriptor is not supported by the product surface.

## Claim 3: "Compute jobs are settled on the Cudos blockchain"

CLAIM: The Cudos chain provides on chain settlement for the compute marketplace, tying token and work together.

REALITY: FALSE. The `cudos-node` chain has no compute, job, workload, or rental module of any kind. Its custom modules are `addressbook`, `admin`, `cudoMint`, `marketplace`, and `nft`, all registered in `app/app.go` alongside the standard Cosmos SDK modules, the Ethereum gravity bridge, and CosmWasm. The one `marketplace` module is an NFT marketplace (its own readme describes it as a module for trading NFTs on the Cudos network), not a compute or job settlement module. A full text search of the chain for compute, job, workload, or rental settlement returns nothing. Compute settlement happens off chain inside the centralized billing system of Claim 2, not on the chain.

EVIDENCE:

```
cudos-node/x/            -> addressbook  admin  cudoMint  marketplace  nft
# the marketplace module is an NFT marketplace ("trading NFTs"), NOT compute/job settlement
grep -riE "compute|job|rental|workload" cudos-node/x/ cudos-node/app/app.go  -> (no matches)

cudos-node/app/app.go (custom app modules registered)
    custombank.NewAppModule(...)
    gravity.NewAppModule(app.GravityKeeper, app.BankKeeper)   // Ethereum bridge
    wasm.NewAppModule(...)                                    // CosmWasm, general contracts
    admin.NewAppModule(appCodec, app.adminKeeper)
    cudoMint.NewAppModule(appCodec, app.cudoMintKeeper)
```

IMPACT: The core "compute settled on chain" thesis has no implementation. The chain and the cloud were always two separate systems, with the chain providing generic Cosmos features (staking, governance, a bridge, CosmWasm for the NFT era) rather than compute settlement.

## Claim 4: "A sovereign Cosmos chain secured by validators and staking"

CLAIM: Cudos runs a Tendermint proof of stake chain where the token is staked to secure the network and earn rewards.

## Claim 5: "CUDOS has active token utility today"

CLAIM: CUDOS is the working utility and security token of a live network.

REALITY: OVERSTATED to the point of being effectively FALSE for the current moment. The chain that gave the token gas, staking, and governance utility is off. What is live is the Ethereum ERC20, whose only present function is to be transferred and swapped, and the project's own guidance is to migrate it to FET. There is no live protocol that consumes CUDOS. ## Claim 6: "CUDOS is merging into ASI and holders migrate to FET"

CLAIM: Cudos joined the Artificial Superintelligence Alliance and CUDOS converts to FET.

REALITY: CONFIRMED. The merger is real and documented by both Cudos and the alliance. The chain README dates the merge to October 28, 2024. Public alliance material and the Cudos merger posts give a fixed conversion of 112.427 CUDOS per FET, with CUDOS entering as a non founding compute member subject to a fee (reported at 5 percent) and a vesting schedule of roughly three to ten months, migrated through the alliance Agent Network Hub. The alliance itself is Fetch.ai plus SingularityNET plus CUDOS, after Ocean Protocol withdrew in 2025.

EVIDENCE:

```
cudos-node/readme.md:1   -> merged into ASI on October 28, 2024, links to docs.cudos.org/docs/asi-merge
```

IMPACT: The migration path is legitimate and orderly. This is the reason the audit treats the deprecation as a wind down rather than an abandonment, and it is why the risk, while high for anyone holding CUDOS as a standalone asset, is not the risk of fraud.

## Positive Findings

* The live ERC20 is clean. Fixed ten billion supply, no post genesis mint, no upgrade proxy, no owner, no pause, and a transfer lock that is already open. Contract level risk is genuinely low, and the deployed bytecode matches the published verified source.
* The project is transparent about its own deprecation. The very first line of the chain repository states the chain is not running and links to the merger docs. That candor is rare and materially reduces the chance of a holder being blindsided.
* The historical Cosmos chain was real, not vaporware. It shipped standard Tendermint staking, governance, slashing, an Ethereum gravity bridge, CosmWasm, and a bespoke `cudoMint` inflation curve. Whatever one thinks of the compute framing, the L1 engineering existed and ran.
* There is a real underlying cloud business (Cudo Compute) with a working API, a Terraform provider, and GPU inventory, so the enterprise is not hollow even though it is centralized.
* The migration destination is a large, liquid token (FET), and the conversion terms are published, so holders have a concrete, non trivial exit.

## Conclusion

Cudos is best understood not as a live decentralized compute network but as a centralized cloud business that once operated a genuine Cosmos chain and has now folded its token into the ASI alliance. Tested against code, the flagship claims split cleanly. The token is exactly what it says it is, fixed supply and non upgradeable, which is confirmed on chain. The Cosmos chain with validators and staking was real, which is confirmed in code. But the two headline pillars fail: there is no on chain compute settlement anywhere in the chain, and the compute marketplace is a centralized REST cloud rather than a decentralized one. Most decisively for a present tense reader, the chain is off by the project's own admission and the repository is archived, so the standalone token has no live utility and is being retired in favor of FET.

This earns a FLAGGED score of 43 out of 100. The deduction is not for dishonesty in the deprecation, which is disclosed and orderly, nor for contract risk, which is low. It is because the subject of the audit, CUDOS as an independent decentralized compute network and token, no longer exists as described: the network is deprecated, the DePIN framing overstates a centralized cloud, and any remaining value is a migration claim on another chain's token. Anyone still holding CUDOS should treat it as an in flight conversion to FET rather than an investment in a live Cudos network.

Verdict tally: CONFIRMED IN CODE 3 (Claims 1, 4, 6), OVERSTATED 2 (Claims 2, 5), FALSE 1 (Claim 3).
