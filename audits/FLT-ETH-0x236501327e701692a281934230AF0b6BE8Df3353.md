## Executive Summary

Fluence markets FLT as a fixed one billion supply governance and utility token for its decentralized compute marketplace, and the live Ethereum contract at 0x236501327e701692a281934230AF0b6BE8Df3353 broadly confirms that story. RPC reads return name Fluence, symbol FLT, 18 decimals, and a totalSupply of exactly 1,000,000,000 FLT minted at genesis, and the currently deployed implementation exposes no mint, no burn, no pause, and no transfer fee logic, so day to day the token behaves as a plain OpenZeppelin style ERC20 with voting. The one material gap between marketing simplicity and technical reality is that the token is not an immutable contract at all but a UUPS upgradeable proxy whose logic can be replaced by the owner, a 2 of 4 Gnosis Safe multisig, which means a future upgrade could in principle add minting or pausing that does not exist today. Nothing on the website claims immutability or non mintability, so this is a disclosure and centralization nuance rather than a false claim, and the project is a real venture backed DePIN compute network rather than a scam.

Fluence FLT is a genuine token for a funded decentralized compute project rather than an anonymous deployment, and the onchain facts line up closely with the public tokenomics. The live contract reports a fixed one billion supply created at genesis, 18 decimals, and no active minting, pausing, or transfer fee, so ordinary transfers behave predictably. The most important finding for a due diligence file is that the contract is a UUPS upgradeable proxy controlled by a 2 of 4 multisig, which means the current fixed supply behavior can be changed by an upgrade. Because no marketing copy promises immutability, this is a centralization and disclosure risk rather than a lie. On balance the token earns a PASS with a note to watch upgrade activity on the proxy.

Reading the contract live over public RPC returns name Fluence, symbol FLT, 18 decimals, and a totalSupply of exactly one billion tokens, all matching the canonical address confirmed by Etherscan and Ethplorer. The deployed bytecode is a small ERC1967 proxy that delegates to implementation 0xbdb50eff425fb2b1b67fea21b8420eeb6d99ccc0, and the EIP1967 admin slot is empty while the implementation exposes proxiableUUID and upgradeToAndCall, which is the signature of a UUPS upgradeable design. The active implementation contains no mint, burn, pause, or fee selectors, so today the token is effectively fixed supply and non pausable. Ownership resolves to a Gnosis Safe version 1.3.0 multisig with a threshold of two out of four signers, which holds the upgrade and administrative power. The practical risk is therefore not hidden minting in the current code but the standing ability of that multisig to upgrade the logic later.

## 2. Onchain Security Assessment (MEFAI analysis)

- totalSupply is 1,000,000,000 FLT (raw 1000000000000000000000000000 at 18 decimals); CoinGecko lists total and max supply both at 1B with roughly 255M circulating, so there is no supply above the stated cap.
- owner() returns 0x7f629403fdcc02ad83aa5debd1d4b1548982afac, which is a Gnosis Safe version 1.3.0 multisig with a threshold of 2 and four signer keys (0xbe8c3dd6..., 0x179819e8..., 0x6d3ef640..., 0x11e41ee1...).
- No mint or emission function is present in the active implementation; the one billion supply was created at genesis in February 2024 and ongoing circulation growth comes from vesting unlocks of existing tokens, not new issuance.
- The contract is a UUPS upgradeable ERC1967 proxy (implementation 0xbdb50eff425fb2b1b67fea21b8420eeb6d99ccc0, EIP1967 admin slot empty, proxiableUUID and upgradeToAndCall present); it is not pausable (paused() reverts, no pause selector), has no fee on transfer, and uses 18 decimals.

## 3. Claim versus Reality

- "1,000,000,000 FLT total supply" / Reality: confirmed onchain, totalSupply reads exactly one billion with 18 decimals and market data shows max supply equal to total supply.
- "FLT holders may create and vote for governance proposals using the Governor model" / Reality: consistent, the active logic is an OpenZeppelin voting style ERC20 with ownership under a multisig, matching a Governor and DAO design.
- Implied simple fixed supply token / Reality: the token is a UUPS upgradeable proxy, so the logic including any future mint or pause is replaceable by the owner multisig; the website does not disclose the proxy or the upgrade key.
- Buyback and deflationary framing seen in some Fluence blog posts / Reality: there is no onchain burn function in the token, so any buyback reduces float by treasury holding on the open market rather than by a contract level burn.

The Fluence website and tokenomics blog describe FLT as a one billion supply governance and utility token that pays for and secures compute capacity, with team and investor allocations vesting over roughly two years and rewards flowing to providers and developers. These statements are internally consistent and match the onchain supply and the observed vesting driven growth in circulating tokens. The site does not mention that the token is deployed behind an upgradeable proxy, nor does it name the multisig that can upgrade it, so a reader would reasonably assume a simple immutable ERC20. Some Fluence articles emphasize buyback driven deflation, which is an economic policy executed on the open market and not an onchain burn built into the token. Overall the marketing is accurate about supply and governance but understates the upgrade authority that exists in the deployed code.

## 4. Website and Frontend Integrity

VERDICT: CLEAN | CONFIDENCE: high

The apex fluence.network issues a 308 redirect to www.fluence.network, a static Framer hosted marketing site whose HTML and only JavaScript bundle (framerusercontent.com script_main plus events.framer.com and Google Analytics gtag) contain zero blockchain addresses, so nothing can differ from or spoof the official FLT contract, and there is no wallet connect, approve, permit, transferFrom, signTypedData, or any web3 drainer code anywhere on the homepage. No obfuscation, eval, atob, base64 payloads, or untrusted remote script hosts appear; all assets load from the site's own Framer hosting and standard analytics, while token, staking, and stats live behind separate linked subdomains rather than any hardcoded fake metric. The only claimed credentials are compliance statements (GDPR, ISO 27001, SOC2) presented as text, with no unbacked third party smart contract audit badge on the page. One anomaly: an initial fetch of the naked apex transiently returned another tenant's cached page (Vanar, onvanar.com) from the shared Cloudflare and Framer edge, which was not reproducible on immediate refetch and itself carried no drainer code, consistent with a benign shared CDN cache collision rather than a compromise of Fluence. Overall the public homepage is a clean informational site with no user funds risk.
