# 0G (0G): Whitepaper Claims vs Code Reality

**Score: 76/100, RISK: MEDIUM**

Date: 2026-08-05

Token (live, independently confirmed): Two faces of one asset.
1. Native gas coin `0G` on the 0G Chain "Aristotle" mainnet, EVM chain ID `16661`. Confirmed live over the public RPC `https://evmrpc.0g.ai`: `eth_chainId` returned `0x4115` (16661) and `eth_blockNumber` returned `0x26eecc8` (block height about 40.8 million), so the chain is producing blocks.
2. A tradeable ERC-20 / BEP-20 representation of `0G` on Ethereum and BNB Chain at `0x4b948d64dE1F71fCd12fB586f4c776421a35b3eE`. Verified directly against an Ethereum public RPC: `name()` and `symbol()` both decode to `0G`, `decimals()` returns `0x12` (18). This contract is a LayerZero Omnichain Fungible Token (OFT), not a plain mint: its bytecode exposes `lzReceive` (`0xd045a0dc`) and `peers` (`0xbb0b6a53`) selectors, and its `totalSupply()` on Ethereum was only `29,497.13` tokens at query time because that is merely the portion bridged onto Ethereum, not the whole float. `owner()` returned `0x7a0cceb3b172ec11eaff88715ef7246a1abbb4d2`, and `eth_getCode` on that address returned `0x`, meaning the owner is an externally owned account (a single key), not a multisig or timelock. Fixed maximum supply is 1,000,000,000; circulating supply around 213 million; market capitalization roughly 386 million USD across about 181 markets at the time public trackers were sampled.

Websites: `https://0g.ai`, docs at `https://docs.0g.ai`, explorers `https://chainscan.0g.ai` and `https://explorer.0g.ai`.

## Why This Report Exists

0G markets itself as "the world's first decentralized AI operating system," a modular AI focused layer 1 that bundles data availability, decentralized storage, and on chain AI compute settlement. Projects that wrap that much narrative around an AI story frequently ship far less than the pitch. The purpose here is narrow and mechanical: open the actual public source and the live chain, and check whether each flagship capability exists as running code or only as slide deck prose. No team, founder, or funding analysis is performed. Everything below is read only from public repositories and public RPC endpoints.

## Method

Five core repositories plus the two chain release repositories were cloned at depth one and read directly. The DA signing path, the storage proof of random access miner, and the AI serving settlement contract were traced line by line. The token was not taken from any listing site: its identity was reconstructed from raw `eth_call` results against an Ethereum public node and from the 0G EVM RPC. Marketing wording was pulled from the project blog, docs, and whitepaper for comparison against what the code enforces. Each claim is graded CONFIRMED IN CODE, OVERSTATED, or FALSE, with a repository path, file, line, and a short verbatim snippet.

## The Foundation: real multi repository engineering, one closed core

This is not vaporware. The DA layer, the storage layer, the AI serving broker, the settlement contracts, and a full go-ethereum execution fork are all present, internally consistent, and genuinely implemented. The single structural surprise is that the consensus state machine that actually runs mainnet is not published as source. Both `0gchain-Aristotle` and `0gchain-NG` contain nothing but a `README.md` pointing at binary releases:

```text
0gchain-Aristotle/README.md
  "0gchain mainnet release repo"
0gchain-NG/README.md
  "0gchain-ng: release for 0g-chain testnet Galileo"
```

The auditable open code is therefore broad: the DA, storage, and serving stacks, the EVM execution engine `0g-geth`, and public forks of the BFT engine (`0glabs/cometbft`) and the alternative execution stack (`0g-reth`, `revm`, `alloy-evm`), plus an older `0g-chain` Cosmos application that was public and has since been removed. What ships only as a compiled binary is the assembled mainnet node itself, `0gchain-Aristotle` (and the testnet `0gchain-NG` under the `0gfoundation` org), with its wired privileged application modules. So the consensus stack is more open than a first glance suggests, but the node that actually runs mainnet still cannot be built from source. That single fact colors the centralization and openness findings that follow.

## Claim 1: A genuine decentralized data availability layer with sampling and on chain verification

**CLAIM:**
> 0G DA supports Erasure Coding, KZG Commitments (AMT protocol), a Verifiable Random Function for availability sampling, quorum based and sampling based verification, and a separate validator network that finalizes proofs submitted by DA nodes.

**REALITY:** CONFIRMED IN CODE (with one terminology caveat).

The DA node is a staked BLS attestation network in the EigenDA family, plus a real on chain sampling game. A signer must stake and register a BN254 public key on chain before it can participate:

**EVIDENCE:**
```rust
// 0g-da-node/server/src/main.rs:76
chain_state.check_staked(ctx.config.amount_to_stake).await?;
chain_state.check_signer_registration(
    ctx.config.signer_bls_private_key, ctx.config.socket_address.clone(),
).await?;
```
```rust
// 0g-da-node/grpc/src/service.rs:132  (verify slices, then BLS-sign the commitment)
let hash = blob_verified_hash(storage_root, req.epoch, req.quorum_id, erasure_commitment);
let signature = (hash * self.signer_bls_private_key).into_affine();
```
Signers are aggregated on chain through the `IDASigners` contract (functions `registerSigner`, `getAggPkG1`, `registeredEpoch`, `quorumCount`), and a separate proof of custody sampling round is verified on chain through `IDASample`:
```jsonc
// 0g-da-node/abis/IDASample.json
event NewSampleRound(uint256 sampleRound, uint256 sampleHeight, bytes32 sampleSeed, uint256 podasTarget)
function submitSamplingResponse(tuple rep)
```
```rust
// 0g-da-node/da-miner/src/submitter.rs:96  (only submit if the data root is committed on chain)
let commitment_exists = self.da_contract
    .commitment_exists(response.data_root, response.epoch.into(), response.quorum_id.into())
    .call().await ...;
// then: self.da_contract.submit_sampling_response(response)
```
The sampling "quality" is a keccak based proof that the node actually holds the sampled line and subline of erasure coded data (`0g-da-node/da-miner/src/mine.rs:8` `calculate_line_quality`, `:37` `calculate_data_quality`), which must beat the on chain `podasTarget`. This is a legitimate proof of data availability by random access, verified by a contract.

Caveat: this is attestation plus proof of custody sampling (the sample seed is drawn on chain), not Celestia style light client data availability sampling, and the README wording "Verifiable Random Function" overstates a seed that is simply produced on chain per round. The substance of decentralized, staked, on chain verified DA is real.

**IMPACT:** Low. The engineering is genuine; only the "VRF" and "sampling" vocabulary is looser than the mechanism.

## Claim 2: Decentralized storage with proof of storage and erasure coding

**CLAIM:**
> 0G Storage uses the PoRA (Proof of Random Access) mining algorithm to mitigate data outsourcing and to ensure rewards go to nodes that actually store the data, with erasure coding for redundancy and sharding for parallelism.

**REALITY:** CONFIRMED IN CODE.

PoRA is implemented as a real mining loop: the node derives a recall position, loads its own sealed data at that position, mixes it with a scratch pad, and only wins if the resulting quality beats an on chain difficulty target.

**EVIDENCE:**
```rust
// 0g-storage-node/node/miner/src/pora.rs:106
let quality = self.pora(idx, &sealed_data, pad_seed);
// :111
if quality <= (self.pora_target / difficulty_scale_x64) << 64 {
    // Find a PoRA valid answer ...
    // :129
    recall_position: recall_position + idx as u64 * SECTORS_PER_SEAL as u64,
```
The recall target comes from the on chain `PoraMine` contract (`0g-storage-node/node/miner/src/miner_id.rs:3` imports `PoraMine`, `pora_mine::MineContext`), and data roots are committed through a flow contract verified against a Merkle tree (`common/append_merkle`). Sealing (`sealer.rs`) binds stored data to the miner identity so a node cannot answer a recall challenge without physically holding the sealed bytes. This is a faithful proof of storage design, not a placeholder.

**IMPACT:** Informational. Storage is one of the strongest parts of the codebase.

## Claim 3: On chain AI serving and inference settlement

**CLAIM:**
> The 0G Compute Network turns AI services into verifiable, revenue generating endpoints, with automated billing and settlement and "trust through TEE verification."

**REALITY:** CONFIRMED IN CODE as a settlement rail, OVERSTATED as "verifiable inference."

Settlement is real and on chain. A provider submits a batch of settlements, each carrying an EIP-712 signature; the contract recovers the signer and only pays out if that signer matches the service's acknowledged TEE key, then transfers user funds to the provider.

**EVIDENCE:**
```solidity
// 0g-serving-contract/contracts/inference/InferenceServing.sol:537
function settleFeesWithTEE(TEESettlementData[] calldata settlements) external nonReentrant ...
// :612  gate on the TEE signer
if (!_verifySignature(settlement, service.teeSignerAddress)) { ... }
```
```solidity
// InferenceServing.sol _verifySignature
(address recovered, ECDSA.RecoverError error) = ECDSA.tryRecover(digest, settlement.signature);
return error == ECDSA.RecoverError.NoError && recovered == expectedSigner;
```
The full off chain broker (inference proxy, fine tuning executor, settlement poller, TEE integration) exists in `0g-serving-broker` (`api/inference`, `api/fine-tuning/internal/services/finalizer.go`, `settlement_tee.go`), so this is a shipped product, not a stub.

The caveat is important. Correctness of the billed amount is asserted by a trusted execution environment key, not proven on chain. The chain checks an ECDSA signature; it does not verify that any inference actually ran or that the token count is honest. "Verifiable AI" here means "attested by hardware the provider registered," which is a trust assumption, not trustless computation. The trusted key is set through owner and provider controlled paths (`acknowledgeTEESignerByOwner(address) external onlyOwner`, `InferenceServing.sol:215`).

**IMPACT:** Medium. Real settlement, but the "verifiable" framing leans on TEE trust rather than on chain verification.

## Claim 4: A real BFT proof of stake layer 1, not a testnet

**CLAIM:**
> 0G Chain is a live layer 1 that uses an optimized CometBFT consensus, is EVM compatible, and separates execution from consensus for high throughput.

**REALITY:** CONFIRMED IN CODE that mainnet is live and EVM real; OVERSTATED on openness and decentralization.

Mainnet "Aristotle" is genuinely live (chain ID 16661, block height about 40.8 million from its own RPC). The execution layer is a real go-ethereum fork with a 0G specific native token precompile:

**EVIDENCE:**
```go
// 0g-geth/core/vm/contracts.go:60
(&WrappedA0giBasePrecompile{}).Address(): NewWrappedA0giBasePrecompile(),
```
The presence of a `beacon` consensus package in `0g-geth/consensus` is consistent with an externally driven consensus client (the closed CometBFT based node) feeding this execution engine, matching the "execution separated from consensus" description. Public reporting puts the validator set around 54 and median daily active addresses near 1,230, which is a working but modest network.

The overstatement is openness. The consensus state machine that finalizes mainnet is distributed only as a binary (see The Foundation above); an independent auditor cannot read the staking, governance, minting, or any privileged authority module for the chain that actually secures the token. A "decentralized" layer 1 whose core node is closed source, run by roughly 54 validators, is real but not as open or as decentralized as the marketing implies.

**IMPACT:** High. The core security node of the flagship product is not publicly auditable.

## Claim 5: "The world's first decentralized AI operating system"

**CLAIM:**
> 0G Ecosystem Receives 290M in Financing to Develop World's First Decentralized AI Operating System.

**REALITY:** OVERSTATED (unfalsifiable marketing).

Nothing in any repository implements or defines an "operating system." The code is a DA network, a storage network, an AI serving broker, and an EVM chain. "Operating system" and "world's first" are positioning language with no on chain or in code referent. The underlying components are real; the superlative is not a technical claim and cannot be verified or credited.

**IMPACT:** Informational.

## Claim 6: 50 GB per second data availability, 50,000 times Ethereum Danksharding

**CLAIM:**
> Each consensus partition can deliver 50 GB per second data availability throughput, about 50,000 times higher than Ethereum's Danksharding design.

**REALITY:** OVERSTATED (not verifiable from node code).

The DA node code confirms the mechanism (erasure coding, KZG, BLS attestation, on chain sampling) but contains no evidence of a 50 GB per second sustained throughput, and such a figure is a function of hardware, bandwidth, and quorum size, not something the published node enforces or benchmarks. It is a theoretical ceiling presented as a headline number. Treat it as aspirational, not measured.

**IMPACT:** Medium. The number shapes the entire pitch yet has no anchor in the auditable code.

## Claim 7: Token utility and decentralization

**CLAIM:** 0G is the decentralized native asset securing and paying for the network.

**REALITY:** Native gas coin CONFIRMED; the tradeable bridged token's control is OVERSTATED as decentralized.

Native `0G` genuinely functions as gas on chain 16661 and is staked by DA signers (`da_registry.stake()`, `signers_handler.rs:88`) and storage miners, and providers must stake to serve (`MIN_PROVIDER_STAKE = 100 ether`, `InferenceServing.sol`). That utility is real. However, the asset that people actually buy and sell on Ethereum and BNB Chain is a LayerZero OFT whose `owner()` is a single externally owned account (`0x7a0c...b4d2`, `eth_getCode` returned `0x`). An OFT owner controls peer configuration and bridge parameters, so the cross chain float sits behind one key with no on chain multisig or timelock visible.

**EVIDENCE:**
```text
eth_call name()     -> "0G"
eth_call symbol()   -> "0G"
eth_call decimals() -> 18
eth_call owner()    -> 0x7a0cceb3b172ec11eaff88715ef7246a1abbb4d2 (getCode = 0x, an EOA)
bytecode selectors  -> lzReceive(0xd045a0dc), peers(0xbb0b6a53)  => LayerZero OFT
```

**IMPACT:** High. Single key ownership of the omnichain bridge token is a real centralization and custody risk for holders.

## Positive Findings

- The data availability node is genuinely engineered: staked BN254 signers, KZG verified erasure coded slices, aggregate BLS attestation registered on chain, and an on chain proof of custody sampling round (`IDASample.submitSamplingResponse`, `podasTarget`). This is serious cryptographic work, not marketing.
- Storage proof of random access is fully implemented, including data sealing bound to miner identity and an on chain difficulty target (`node/miner/src/pora.rs`).
- On chain AI settlement is a working rail with EIP-712 signatures, replay protection via nonces, partial settlement handling, and a full broker for both inference and fine tuning.
- The execution layer is a real, customized go-ethereum fork with a native token precompile, and mainnet is demonstrably live and producing blocks at chain ID 16661.
- The token is real, liquid, and widely listed; the native gas and staking utility is enforced by the contracts and node code, not merely asserted.

## Conclusion

0G is a substantively built project. Three of its four flagship technical claims (decentralized DA with on chain sampling, proof of random access storage, and on chain AI settlement) are confirmed in real, coherent, cross referenced source, and its mainnet is genuinely live with a tradeable token. That places it firmly in Passed territory. The deductions are honest and specific: the node that actually secures mainnet is distributed only as a compiled binary and cannot be built from source, even though much of the surrounding stack (including the CometBFT and reth forks) is public; the serving contracts are upgradeable proxies under an `Ownable` owner that also sets the trusted TEE signer; the tradeable omnichain token is owned by a single externally owned account; and the two loudest marketing lines ("world's first decentralized AI operating system" and "50 GB per second, 50,000 times Danksharding") have no anchor in the auditable code. None of these are fraud; together they justify a MEDIUM risk rating rather than LOW. Real engineering, real chain, real token, with a closed core and overstated superlatives.
