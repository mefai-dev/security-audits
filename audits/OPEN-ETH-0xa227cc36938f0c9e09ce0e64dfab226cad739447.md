# OpenLedger (OPEN): Whitepaper Claims vs Code Reality

**Score: 62/100, RISK MEDIUM**

Date: 2026-08-05
Auditor: MEFAI Security (ICE/ION deep source audit, read only, public sources)

**Token (live, independently confirmed via Ethereum RPC and published source):**
- Chain: Ethereum mainnet (L1). The tradeable OPEN asset is an ERC20 here.
- Contract: `0xa227cc36938f0c9e09ce0e64dfab226cad739447`
- Name `Open`, Symbol `OPEN`, Decimals `18`, Total supply `1,000,000,000` OPEN (`1e27` base units)
- Implementation: OpenZeppelin v5 `ERC20` plus `ERC20Burnable`, Solidity `0.8.27`. Fixed supply minted once in the constructor. No `mint`, no `owner`, no pause, no AccessControl, not a proxy (not upgradeable). Immutable and ownerless.
- OPEN is also the native gas token of the OpenLedger OP Stack L2 (chain id `1612`). `WOPEN` (wrapped) and `GOPEN` (governance stake) are sister contracts. Cross chain movement uses a LayerZero OFT adapter (`openledger-dev/openledger-layerzero-native`).

**Websites:** https://www.openledger.xyz , app + explorer https://scan.openledger.xyz , docs https://openledger.gitbook.io/openledger , staking https://stake.openledgerfoundation.com

**GitHub:** The project's brand name is `OpenLedgerHQ` (its X handle is `@OpenledgerHQ`), but the official website links no source repository anywhere, and `github.com/OpenLedgerHQ` returns HTTP 404 with GitHub API `Not Found`, so no first party GitHub organization exists under the marketed brand name. The only public first party source lives under an unadvertised GitHub organization, `github.com/openledger-dev`, and covers the token, governance, staking, and LayerZero bridge contracts (plus a fork of the generic `easy-dataset` fine tuning tool), but none of the proprietary AI core.

## Why This Report Exists

OpenLedger markets itself as "the AI blockchain" where "data, models, and intelligent agents evolve onchain," with Proof of Attribution that cryptographically traces model outputs back to data contributors and pays them in real time. Those are strong, testable engineering claims. This report reads the actual published source, the deployed bytecode, and the live chain state, then grades each flagship claim as CONFIRMED IN CODE, OVERSTATED, or FALSE. The token contract is included but treated as secondary. No team, founder, or personnel analysis is performed.

The short version: the chain is a genuine OP Stack rollup, the token is a clean immutable ERC20, and the attribution research is real and published. But the attribution computation, datanet validation, model training, and inference all run offchain in closed source services, and the reward layer settles through a single offchain signer key. The chain stores hashes and pays out results; it does not compute or verify the intelligence. That gap between "onchain AI" marketing and offchain reality is the substance of this audit.

## Method

1. Confirmed the live token by calling `name`, `symbol`, `decimals`, `totalSupply`, `owner`, and `paused` on the L1 contract through a public Ethereum RPC, then decoded the runtime bytecode selectors and checked the two `EIP-1967` proxy storage slots.
2. Confirmed the L2 is live by querying `eth_chainId` and `eth_blockNumber` on `https://rpc.openledger.xyz`.
3. Read the published first party Solidity under `github.com/openledger-dev` (`openledger`, `openledger-staking`) and matched `Open.sol` byte for byte against the deployed bytecode.
4. Read the whitepaper "Proof of Attribution: Powering Explainable and Payable AI on OpenLedger" (June 2025) and the GitBook documentation (attribution pipeline, contracts, datanet contribution, chain config, predeployed contracts) for verbatim claims.
5. Enumerated GitHub for any org publishing the attribution engine, datanet, or model contracts.

## The Foundation: a real OP Stack L2 with an offchain AI stack

OpenLedger is a real Ethereum L2 built on the OP Stack with EigenDA for data availability and settlement on Ethereum. This is confirmed on the live chain and by the predeployed contract set.

```
# Live L1 token (Ethereum mainnet), public RPC eth_call results
name()        -> "Open"
symbol()      -> "OPEN"
decimals()    -> 18
totalSupply() -> 1e27  (1,000,000,000 OPEN)
owner()       -> execution reverted (no owner function)
paused()      -> execution reverted (no pausable)
EIP-1967 implementation slot -> 0x0 (not a proxy, not upgradeable)

# Live L2 (OpenLedger mainnet), https://rpc.openledger.xyz
eth_chainId    -> 0x64c  (1612)
eth_blockNumber-> 0x102db9b  (~16.96M blocks, chain is producing)
```

The predeployed contracts documented for the network are the standard OP Stack fault proof suite: `OptimismPortal2`, `DisputeGameFactory`, `L2OutputOracle`, `AnchorStateRegistry`, `SystemConfig`, `SuperchainConfig`, `DelayedWETH`, `Mips`, and `PreimageOracle`, with `Safe` multisig owners and a guardian. That is a legitimate rollup, but it is also a Stage 0 configuration: a team run sequencer and multisig upgradeable system contracts. Nothing about the OP Stack layer is AI specific; the AI value proposition lives in a separate application layer and in offchain services.

Product reality: mainnet launched 18 November 2025. OPEN debuted on Binance in September 2025 and is tradeable there and on other venues; the L1 ERC20 above is the canonical tradeable asset. The project raised an 8 million dollar seed led by Polychain Capital and Borderless Capital. At audit time the token was reported trading well below launch levels. The consumer "node" is a Chrome extension and desktop uptime client that farms points ("Ensure your node stays online to reach the hourly cap"); it is not a consensus node.

## Claim 1: Proof of Attribution is an onchain, trustless mechanism

**CLAIM:**
> "Data contributions are permanently recorded on chain, preventing unauthorised modifications." ... "Verifiable Data Contributions: Ensures that every data point used in AI models can be traced back to its contributor." (docs, `proof-of-attribution.md`)
> "This attribution must be both precise and scalable ... For small, specialized models, influence is computed using gradient-based methods ... For large language models, attribution is derived by comparing output tokens against a compressed representation of the training corpus." (whitepaper, Section 1)

**REALITY: OVERSTATED.** The attribution algorithm is real and reasonably documented: influence function approximations (Hessian based, layer wise) for small models, and an `Infini-gram` suffix array token matcher for large models. But every step that produces an attribution score runs offchain, and the code that runs it is not public. The chain receives only the finished numbers plus hashes. There is no onchain recomputation, no fraud proof, and no zero knowledge proof that the reported influence weights are correct. "Trustless" and "verifiable" therefore mean "immutably recorded," not "independently checkable." A contributor must trust OpenLedger's offchain engine and its privileged signer.

**EVIDENCE:**
```
whitepaper (Proof of Attribution, June 2025), Attribution Aggregation section:
  "Once token-level or gradient-level influence scores are computed, either
   through span matching (Section 5) or influence functions (Section 4), the
   next step is to elevate these attributions to the level of DataNets."
  "These weights ... become the basis for reward distribution and are recorded
   on chain along with model identifiers, output hashes, and attribution metadata."

whitepaper, DataNet submission sequence:
  "The content is stored off chain and made available through DA layer, while
   the metadata and hash are committed to the DataNet contract on chain."

docs data-attribution-pipeline.md:23
  "Influence scores are calculated to determine the quality and relevance of
   each contribution."   (no location or verifier stated; computation is offchain)
```
The whitepaper never claims the influence computation runs onchain, and it cannot: influence functions require gradients and Hessian inverses, and `Infini-gram` requires a suffix array over a trillion token corpus. Both are heavy offchain machine learning workloads. What is onchain is a record of the output.

**IMPACT:** The signature claim of the project, provable attribution, reduces in code to an offchain oracle writing scores to an immutable log. Users cannot verify that the scores, and therefore the payouts, are honest or free of manipulation. This is a trust and transparency risk, not a solvency risk.

## Claim 2: Datanets are decentralized onchain data networks

**CLAIM:**
> "Datanets are decentralized networks for contributing and licensing specialized datasets." (marketing)
> "Each dataset is attributed on chain, ensuring transparency and verifiability." (docs `data-attribution-pipeline.md:12`)

**REALITY: OVERSTATED.** A Datanet is an onchain contract that stores a hash and metadata per data point; the actual files are stored offchain on the DA layer, and contribution validation is a centralized offchain service. The onchain `Model` contract that backs a Datanet is upgradeable and admin gated, so even the onchain record is mutable by the operator.

**EVIDENCE:**
```
docs openledger-contracts.md:7 (Model Contract)
  "Other users can contribute data, which gets hashed and anchored into the
   contract as data points. Over time, contributed data undergoes a validation
   process, and appropriate contributors receive rewards ..."
docs openledger-contracts.md:12
  "Implements an upgradeable pattern using ERC1967 with Beacon Proxy ..."

docs datanet-contribution.md:37, 47, 79 (centralized offchain validation)
  "For accepted contributions, a validation score is assigned ..."
  "Per User Limit: 10 MB total upload capacity per day ..."
  "The leaderboard is refreshed automatically every one hour ..."
```
Daily megabyte caps, automatic accept or reject, validation scores, and an hourly refreshed leaderboard are the behaviors of a centralized web application with onchain anchoring, not of a decentralized network.

**IMPACT:** "Decentralized data network" describes the anchoring, not the control. Who may contribute, what passes validation, and what score a contribution receives are all decided offchain by OpenLedger.

## Claim 3: Dataset uploads, model training, and inference are executed onchain

**CLAIM:**
> "All actions such as dataset uploads, model training, reward credits, and governance participation are executed on chain." (docs `what-is-openledger.md:5`)

**REALITY: FALSE.** Model training and inference run offchain on GPUs. The same documentation page contradicts the claim two paragraphs later by describing GPU deployment, and the whitepaper confirms content and compute are offchain. Only provenance logs and reward settlement are onchain.

**EVIDENCE:**
```
docs what-is-openledger.md:19 (same page as the claim)
  "It supports advanced techniques that allow multiple models to be deployed
   efficiently on a single GPU, drastically improving performance and cost
   savings. Every contribution ... is tracked through the blockchain ..."
   (deployment is on a GPU; the blockchain only tracks)

whitepaper Section 1
  "For small, specialized models, influence is computed using gradient-based
   methods ..."  (offchain training and scoring)
```
Training on a GPU with results tracked onchain is the opposite of training executed onchain. The OpenLoRA serving system and ModelFactory fine tuning tool are offchain products with no public source.

**IMPACT:** The strongest literal claim on the front page is false as written. The honest framing, which the whitepaper mostly uses, is that compute is offchain and settlement is onchain. Readers relying on the "executed on chain" phrasing are misled about where the intelligence and the trust actually sit.

The mainnet L2 is live at chain id `1612`, is producing blocks, exposes an OP Stack RPC and explorer, and its predeployed contract set is the standard OP Stack plus fault proof suite. This is a real rollup, not a database with a token.

## Claim 5: Attribution rewards are verifiable and trustless (reward and control layer)

**CLAIM:** Contributors are rewarded "fairly for the attribution," through a "provable and trustless attribution system." (docs `what-is-openledger.md:15`, `data-attribution-pipeline.md:36`)

**REALITY: OVERSTATED, and the central centralization finding.** The published staking and dispersal code shows rewards are released by presenting a signature from a single `signer` address controlled by the project, gated by a `PROJECT_ADMIN` role. Whatever the offchain engine decides, an offchain key signs, and the contract pays. Combined with fully upgradeable, admin gated application contracts and a Stage 0 OP Stack (single sequencer, multisig upgrade authority), the reward and control surface is centralized.

**EVIDENCE:**
```
openledger-dev/openledger-staking : src/SigDispersal.sol
  contract SigDispersal is OwnableRoles {
      address public signer;   // address signing the claims
      address public vault;
      ...
      uint256 public constant PROJECT_ADMIN = _ROLE_0;
  // claims are validated against ECDSA signatures from `signer`
  // (solady ECDSA + OwnableRoles); a single offchain key authorizes payouts

docs openledger-contracts.md:31,41,45  (all app contracts upgradeable)
  GasDistributor  -> "UUPS-upgradeable"
  Operator        -> "UUPS upgradeable ... entry point for relayers ...
                      enforces role-based access control across all contracts"
  ModelTokenFactory -> "UUPS upgradeable"
  Model / ModelFactory -> ERC1967 Beacon Proxy (bulk upgradeable)
```

**IMPACT:** The reward path is trust based. A compromised or dishonest `signer`, or an admin upgrade of the `Model`, `Operator`, or `ModelTokenFactory` proxies, could redirect or fabricate rewards and alter recorded attributions. This is the primary technical risk in the system and is the concrete reason the "trustless" framing is overstated.

## Claim 6: The OPEN token and governance are as described

**CLAIM:** OPEN is the network token; governance is "powered by hybrid on chain system using OpenZeppelin's modular Governor framework." (docs `what-is-openledger.md:27`)

**REALITY: CONFIRMED IN CODE (positive).** The published `Open.sol` matches the deployed bytecode exactly and is a minimal, immutable, ownerless fixed supply ERC20 with burn. Governance is a real OpenZeppelin `Governor` (`OpenLedgerGovernor.sol`) with a `GOPEN` vote token. These are the parts that are both onchain and open source.

**EVIDENCE:**
```
openledger-dev/openledger : contracts/Open.sol  (matches deployed bytecode)
  contract Open is ERC20, ERC20Burnable {
      string internal constant NAME = "Open";
      string internal constant SYMBOL = "OPEN";
      constructor(address recipient) ERC20(NAME, SYMBOL) {
          _mint(recipient, 1_000_000_000 * 10 ** decimals());
      }
  }
  // no mint function, no Ownable, no Pausable, no proxy -> supply is fixed
  // and authorities are absent. Deployed selector scan confirms only
  // transfer/approve/burn/burnFrom plus OZ v5 custom errors.
```

**IMPACT:** Positive. The asset holders actually hold on Ethereum cannot be inflated, frozen, seized, or upgraded. The token itself is low risk; the risk lives in the offchain and application layers, not in the ERC20.

## Positive Findings

- The tradeable L1 OPEN token is a clean OpenZeppelin v5 `ERC20Burnable` with a fixed 1 billion supply, no mint, no owner, no pause, and no proxy. Source matches deployed bytecode. This is a genuinely low risk token contract.
- The L2 is a real, live OP Stack rollup with EigenDA data availability and the standard fault proof predeploy suite. It is not a database pretending to be a chain.
- Proof of Attribution is backed by a substantive, publicly published research paper that names concrete methods (influence function approximation and `Infini-gram` suffix array attribution) and is candid that content is stored offchain and influence is computed with gradient based methods.
- Token, wrapped token, governance token, the OpenZeppelin `Governor`, and the staking and dispersal contracts are open source and reviewable.
- Real backing and distribution: Polychain and Borderless seed round, Binance listing, live mainnet since November 2025.

## Conclusion

OpenLedger is a legitimate, funded, live project, not a scam, and its token is one of the cleaner ERC20 contracts a holder can own. Its foundational claim, that it is a real EVM L2, is true. Its flagship claim, that Proof of Attribution runs onchain in a trustless and verifiable way, is overstated: the attribution engine, datanet validation, model training, and inference are all offchain and closed source, and the reward layer settles through a single offchain signer against upgradeable, admin controlled contracts. The most literal marketing statement, that model training is executed onchain, is false; only provenance and settlement are onchain. A material transparency gap compounds this, since no GitHub organization exists under the project's own brand name, `OpenLedgerHQ` (the site links no source at all), and the only public first party source, hosted under an unadvertised GitHub organization, covers the token and governance layer but none of the AI core.

The verdict is a low pass. The token and chain are real and the token is safe; the "onchain AI" narrative is substantially offchain and trust based, and the parts that matter most for the value proposition are neither verifiable nor open. Investors and integrators should treat OpenLedger as centralized AI infrastructure with an onchain settlement and token layer, and should not rely on marketing language implying trustless, onchain attribution or training.

**Score: 62/100 (Passed). Risk: MEDIUM.** Consistent with a real, backed, live project and a clean immutable token (which prevent a Flagged or high risk rating) offset by an offchain, closed source AI core, a single signer reward path, fully upgradeable application contracts, and a missing marketed source repository (which prevent a high score or low risk rating).
