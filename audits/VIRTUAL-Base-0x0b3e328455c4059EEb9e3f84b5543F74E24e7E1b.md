### Claim vs reality
- Tokenized AI agents with bonding curve launches: CONFIRMED IN CODE. `Bonding.sol` plus `FFactory`, `FPair`, `FRouter` implement a bonding curve, and `AgentFactoryV3` plus `AgentToken` mint the graduated agent token. Note the public `launch()` is stubbed, so the exact deployed launch code is not in the repo.
- Graduation at "42,000 $VIRTUAL, a liquidity pool is automatically created and paired with the agent token on Uniswap V2": CONFIRMED IN CODE as a mechanism, with a nuance. `gradThreshold` is a live owner settable variable, not a hardcoded 42,000, so the number is a current parameter rather than an immutable constant.
- 1% agent trading fee split "70% to the agent creator, 30% to Virtuals Treasury": OVERSTATED on traceability. A protocol `fee` and `_feeTo` exist in `Bonding.sol`, but that is a flat launch fee, and the 1% rate and 70 / 30 split are not locatable in the public code I fetched (the fee routing sits outside the readable path, and `launch()` is stubbed). The claim is plausible but not verifiable in open source.
- "LP tokens locked for ten (10) years" on graduation: OVERSTATED on traceability. No explicit ten year lock appears in the `Bonding.sol` graduate path I read; the lock, if present, lives in `FRouter` or `AgentFactory` which I did not confirm line by line. Treat as a claim, not verified in the code fetched.
- Buyback and burn of VIRTUAL: OVERSTATED. The docs describe sniper taxes being "automatically used to buy back agent tokens onchain," which is a buyback of agent tokens, not a burn of VIRTUAL. The popular "buyback and burn VIRTUAL" framing is not what the whitepaper actually states.
- Agent Commerce Protocol (ACP), immutable on chain interaction records: CONFIRMED IN CODE at the contract level. `contracts/acp/ACPSimple.sol` and `contracts/acp/InteractionLedger.sol` exist and are open source.
- Fixed 1,000,000,000 VIRTUAL supply, no arbitrary inflation: CONFIRMED. The origin design caps at `ERC20Capped(1_000_000_000e18)`, market data shows total supply already equals the 1B max, and the Base token mints only through the bridge and OFT paths, so no further inflation is possible.
- Non custodial and transparent: PARTIALLY CONFIRMED. The token is clean and renounced, and a large body of Solidity is public, but the launchpad contracts are upgradeable proxies whose admin I could not independently verify, and the public bonding `launch()` is stubbed, so full transparency is OVERSTATED.

This is a launchpad risk and does not touch the VIRTUAL token itself.
- Low: LayerZero OFT credit provides a cross chain mint path; with `owner()` renounced the peer and delegate config is frozen, but the omnichain trust surface (endpoint delegate and configured peers) still applies as with any OFT.
- Low: the 70 / 30 fee split and the ten year LP lock are docs claims not traceable to the public code fetched.
- Informational: GoPlus sets hidden_owner 1 while the on chain `owner()` is the zero address; this reads as a GoPlus heuristic on the OFT owner and delegate storage rather than an active controller.
- Informational: the Base side supply of 496,880,888.69 is a bridged subset of the 1,000,000,000 global cap, with the balance on Ethereum L1 and Solana.
