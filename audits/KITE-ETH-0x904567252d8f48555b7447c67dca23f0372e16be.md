## Why This Report Exists

Kite AI markets itself as an EVM compatible Layer 1 "built for agentic payments," with a novel three tier agent identity, state channel payment rails, and a Proof of Attributed Intelligence consensus. The token is deeply liquid and backed by well known venture names, which drives strong narrative momentum. The question this report answers is narrow and mechanical: when you read the actual public source in the `gokite-ai` org and query the live chain, how much of the flagship technical story is present in code, how much is a hosted closed service, and how much is roadmap or marketing. The focus is the whole project; the token contract is secondary. No team analysis is performed.

## Method

1. Enumerated the real GitHub org `github.com/gokite-ai` via the GitHub API (38 repos) and read the non fork, project specific repositories directly from `raw.githubusercontent.com`.
2. Queried the live Ethereum token and the live Kite Chain mainnet RPC (`rpc.gokite.ai`) with raw JSON RPC (`eth_call`, `eth_getCode`, `eth_getStorageAt`) to confirm token facts and to inspect proxy implementation and admin slots.
3. Cross read the public developer docs (`docs.gokite.ai`), the mainnet smart contract list, and third party research to extract the exact flagship claims, then traced each claim to code or to its absence.

## The Foundation: an Avalanche L1, a closed Passport service, and a bridged token

Three facts frame everything below.

First, the chain is an Avalanche Layer 1 (subnet). The core chain repos in the org are forks: `avalanchego` (fork), `subnet-evm` (fork), `avalanche-cli` (fork), `avalanche-faucet` (fork), `icm-services` (fork), `op-geth` (a fork of the OP Stack `op-geth`, not an Avalanche repo). The only project specific chain repo, `gokite-ai/gokite-chain`, contains no consensus code at all; it is Docker plus node config, and its node runs `avalanchego` tracking an Avalanche subnet. So Kite Chain is a customized Avalanche L1 running standard `subnet-evm`, not a from scratch chain with novel consensus.

Second, the differentiating product, the "Kite Agent Passport," is a hosted, closed source backend plus two closed CLIs (`kpass`, `ksearch`). The only public artifact is `gokite-ai/passport-skills`, a set of `SKILL.md` instruction files that teach an AI agent how to call those CLIs. The identity and payment logic itself is not in any public repo.

Third, the KITE token is a LayerZero OFT (omnichain fungible token) bridged across Ethereum, BNB Chain, Avalanche, and Kite Chain. This is confirmed by LayerZero OFT selectors in the deployed Ethereum bytecode and by the LayerZero endpoint entries in the mainnet contract list.

## Claim 1: "Purpose built EVM compatible Layer 1 with its own consensus and validators"

CLAIM. Marketing and docs describe Kite Chain as a "purpose-built EVM-compatible L1 designed to serve as the execution and settlement layer for all stablecoin native payments," positioned as its own agentic Layer 1.

REALITY: OVERSTATED. The chain is real and mainnet is live, but it is an Avalanche subnet running forked Avalanche software. Consensus is Avalanche (Snowman family), not a Kite invention. The "L1" label is accurate only in Avalanche's own sense, where a subnet is now called an L1.

EVIDENCE.
```
gokite-ai/gokite-chain/README.md
  docker run ... \
    -e AVALANCHEGO_NETWORK_ID=fuji \
    -e AVALANCHEGO_TRACK_SUBNETS=LN3HF6L6WMdcjLTAwN9gUstNztNoaB4WhsbB3dKsggmJKXBk3 \
    -e AVALANCHEGO_PARTIAL_SYNC_PRIMARY_NETWORK=true \
    ghcr.io/gokite-ai/gokite-chain:latest
# node = avalanchego; Kite is a tracked Avalanche subnet, not custom consensus
```
```
GitHub org gokite-ai forks (git provenance):
  avalanchego (fork), subnet-evm (fork), avalanche-cli (fork),
  avalanche-faucet (fork), icm-services (fork), op-geth (fork)
# the EVM and node layers are standard Avalanche forks
```
```
Live mainnet, verified by RPC:
  POST https://rpc.gokite.ai eth_chainId  -> 0x93e (2366)   # matches LayerZero mainnet doc
  POST https://rpc.gokite.ai eth_blockNumber -> 0x23f4e (147278)
```

IMPACT. The chain exists and works, so "EVM L1, mainnet live" is true. But the "purpose built" and "its own" framing overstates novelty: the consensus, node, and EVM are Avalanche technology. Buyers should price this as an Avalanche L1, whose security and validator model are inherited from Avalanche subnet tooling, not as a bespoke consensus network.

## Claim 2: "Three layer identity (user, agent, session) as verifiable on chain agent identity"

CLAIM. The whitepaper describes an identity model that "separates the user, agent and session into 3 identities called root, delegated and ephemeral authority respectively," using BIP 32 style hierarchical derivation, presented as native, verifiable identity for the agentic web.

REALITY: OVERSTATED. The three tier delegation model is genuinely shipped and usable, which is a real positive. But it is implemented off chain in the closed Passport backend and CLIs, gated by passkeys, and expressed as a signed delegation JSON object, not as auditable on chain identity contracts. The mainnet smart contract list contains no identity, passport, or agent registry contract at all. What is public is only the instruction layer that tells an agent how to drive the closed service.

EVIDENCE.
```
gokite-ai/passport-skills/README.md
  "Kite Agent Passport gives an AI agent a limited, user-approved budget ...
   users sign up, fund a wallet, and approve spending sessions via passkey,
   while agents drive the whole flow through the kpass and ksearch CLIs."
# the logic lives behind kpass/ksearch (closed); repo ships only SKILL.md guides
```
```
gokite-ai/passport-skills/form-session-delegation/references/delegation-schema.md
  {
    "task": { "summary": "string" },
    "payment_policy": { "max_amount_per_tx": "string",
                        "max_total_amount": "string", "ttl_seconds": 3600 },
    "execution_constraints": { "x402": { "scope_mode": "scoped",
                        "allowed_endpoints": [ ... ] } }
  }
# session = ephemeral authority is an off chain signed delegation object with limits + TTL
```
```
docs.gokite.ai mainnet smart contract list:
  Staking, RewardVault, FixedAPRRewardCalculator, ProxyAdmin,
  StakingVault, WKITE, USDC.e, USDT, WETH, Algebra DEX, LayerZero, Multicall3
# NO identity / passport / agent-registry contract is deployed on chain
```

IMPACT. The identity product is real and, judging by the delegation schema, thoughtfully scoped (per transaction cap, total budget, TTL, endpoint allow list). But the value proposition of "verifiable, on chain, permissionless agent identity" is not what is running: the trust anchor is a hosted service you cannot audit and cannot self host from public code. If Kite's backend is down or changes policy, the identity and spending guarantees change with it.

## Claim 3: "Agentic payment rails: state channels for streaming micropayments, plus stablecoin settlement"

CLAIM. The whitepaper claims "state channels for off chain streaming micropayments and inter-agent communication," advertising "sub-100ms latency at roughly 0.000001 per transaction, three orders of magnitude cheaper than Solana."

REALITY: split verdict.
- State channels: FALSE in code. There is no state channel contract, channel manager, dispute or settlement contract anywhere in the public org, and none in the mainnet contract list. The shipped Passport product does not use channels; it settles over `x402` (the Coinbase HTTP 402 standard) and `tempo_http` (Stripe's Tempo stablecoin rail). The two on chain payment style contracts that do exist, `SpendingGuard.sol` and `EscrowService.sol`, live in `example-contracts` and are single owner toy demos with hardcoded limits, explicitly for development only.
- Stablecoin native settlement: CONFIRMED. USDC.e and USDT are deployed on Kite Chain, the docs ship a gasless stablecoin transfer flow, and the delegation constraints target x402 paid endpoints. Agents can actually pay for services.

EVIDENCE.
```
gokite-ai/passport-skills/kite-passport/SKILL.md
  "Passport settles across multiple rails under one session. A catalog service's
   payment_approach (x402 or tempo_http) is just which protocol the merchant uses"
# real settlement = x402 (Coinbase) and Tempo (Stripe). No mention of Kite state channels.
```
```
gokite-ai/example-contracts/contracts/SpendingGuard.sol
  uint256 public constant MAX_DAILY_SPENDS = 3;
  uint256 public constant MAX_SPEND_AMOUNT = 1 ether;
  function spend(uint256 amount, address payable recipient, SpendingCategory category)
      public onlyOwner { ... }
# hardcoded toy demo, single owner, "For Development purpose only" per repo description
```
```
docs.gokite.ai mainnet tokens + kite-chain/8-kite-stablecoin/stablecoin-gasless-transfer.md
  USDC.e 0x7aB6f3ed87C42eF0aDb67Ed95090f8bF5240149e (6 decimals)
  USDT   0x3Fdd283C4c43A60398bf93CA01a8a8BD773a755b (6 decimals)
# stablecoin settlement is real and on chain; gasless transfer documented
```

IMPACT. The concrete, valuable half is true: agents can settle in stablecoins via industry standard rails (x402, Tempo). The headline that makes Kite sound like unique infrastructure, its own state channel network with sub 100ms and near zero cost, is not in the code and is not what the product runs. Those numbers are whitepaper aspiration. Treat the state channel narrative as roadmap, not shipped.

## Claim 4: "Proof of Attributed Intelligence (PoAI) consensus"

CLAIM. Third party research and legacy Kite material describe PoAI as Kite's "unique consensus mechanism" that "measures and rewards verified contributions from AI models and data providers."

REALITY: FALSE as stated. PoAI is not the consensus of Kite Chain. The chain uses Avalanche consensus (see Claim 1). Validator economics are ordinary fixed APR staking, not attribution weighted rewards, as shown by the deployed `FixedAPRRewardCalculator`. PoAI traces to Kite's older 2024 data and AI attribution testnet (the `zetta-aiweb`, `zsource`, `beacon-zrunner`, `language-data-cleaner` repos in the same org), a narrative the payments L1 has largely left behind.

EVIDENCE.

IMPACT. Anyone buying KITE on the belief that the chain runs a novel AI attribution consensus is mistaken. The live chain is Avalanche PoS with fixed APR staking. PoAI, to the extent it survives, is a reward or marketing concept, not a security mechanism.

## Centralization

- Upgradeable core, and already upgraded. `KiteStakingManager` is an EIP 1967 proxy. On chain, its implementation slot resolves to `0x57c5bf4fac5afb98c92ea4151999346cad7494db`, which differs from the implementation address `0x065cA4309a5abc9F1cC2d8fA00634BC948C25C6b` listed in the docs. That mismatch is direct evidence the staking logic has already been upgraded through the admin path. The admin slot resolves to `0x3fa7667fd726f73ef42c66f8715e0c6d37d44905`, the `ProxyAdmin`. `StakingVault` is likewise a proxy. Whoever controls `ProxyAdmin` can rewrite staking and reward logic at will.
```
POST https://rpc.gokite.ai eth_getStorageAt(0x7d627b0F..., <EIP1967 impl slot>)
  -> 0x...57c5bf4fac5afb98c92ea4151999346cad7494db   (docs impl was 0x065cA430...; upgraded)
POST https://rpc.gokite.ai eth_getStorageAt(0x7d627b0F..., <EIP1967 admin slot>)
  -> 0x...3fa7667fd726f73ef42c66f8715e0c6d37d44905   (ProxyAdmin)
```
- Validator set. As an Avalanche L1 with staking gated by `KiteStakingManager`, the validator set is staked and effectively permissioned under foundation control at this stage, consistent with how Avalanche L1s launch. There is no public evidence of an open, permissionless validator set.
- Closed core. The chain layer is open but is a standard Avalanche fork. The part that actually differentiates Kite, the Passport identity and payment backend and the `kpass` and `ksearch` CLIs, is closed source and hosted. This is closed core, not open core.
- Token authority. The Ethereum KITE token is not upgradeable, but it is an OFT with an `owner()` and LayerZero delegate at `0x725e...3fd8` that controls cross chain peers and configuration.

## Product Reality

- Mainnet is genuinely live (chainId 2366, launched April 2026), with staking, an Algebra DEX (a Uniswap v3 style fork), bridged stablecoins, and a LayerZero bridge all deployed. This is a shipping product, not vaporware.
- On chain activity looks early and modest. The mainnet RPC reported block height near 147,278, low for a chain live for several months and far from the "thousands of microtransactions per second" marketing. Real usage appears to be in an early phase.
- The token is very real and liquid: Binance `KITE/USDT` as the primary venue, plus Bitget, OKX, HTX, Paribu, and PancakeSwap, with roughly 32M USD daily volume. Multi chain via LayerZero OFT.
- Narrative momentum is strong and backer driven, with prominent venture names and a large raise cited across coverage. That momentum, plus the Binance listing, explains a roughly 235M USD market cap and about 982M USD FDV against a product whose flagship technical claims (own consensus, state channels, PoAI, on chain identity) are only partly matched by code.

## Positive Findings

- The Agent Passport is a real, working product, not a slideware promise. Agents can authenticate a user via passkey, receive a scoped delegation, and pay for services through x402 and Tempo.
- The delegation model is security conscious: per transaction cap, total budget, TTL, and endpoint scoping are first class, and the public `delegation-schema.md` even warns implementers about shell injection from untrusted `task.summary` values (for example a crafted `Buy $(rm -rf ~)`), showing awareness of agent prompt to command risks.
- Stablecoin settlement is genuinely implemented on chain, including a gasless transfer path, which is the practically useful core of the "payments for agents" thesis.
- Standards alignment is real: the org mirrors and builds on `x402`, Google's A2A, OpenAI and Stripe's Agentic Commerce Protocol, and AP2, rather than inventing closed protocols for the payment negotiation layer.
- The token contract on Ethereum is a plain, non upgradeable OFT, which limits token level rug surface (no mint or upgrade backdoor observed on the Ethereum deployment).

## Conclusion

Kite AI is a legitimate, funded, shipping project with a live mainnet and a genuinely usable agent payment product, and its token is deeply liquid on tier one venues. That is why it passes. But the marketing consistently overstates novelty and decentralization relative to what the code and chain actually do. The chain is an Avalanche L1 fork, not a bespoke consensus network. The celebrated three layer identity is a real product but a closed, hosted backend, not verifiable on chain identity. The flagship state channel rails and Proof of Attributed Intelligence consensus are not present in any public code and are not what the product runs; settlement uses external x402 and Tempo rails, and consensus and rewards are ordinary Avalanche staking with a fixed APR calculator. Centralization is material: the staking logic sits behind an upgradeable proxy that has already been upgraded by an admin controlled ProxyAdmin, and the validators are effectively permissioned. The honest summary is that the useful 60 percent (an Avalanche L1 plus stablecoin settlement plus a scoped delegation product) is real, while the differentiating 40 percent (own consensus, state channels, PoAI, on chain identity) is either roadmap, rebranded legacy narrative, or a closed service.

**Score: 63/100 (Passed). Risk: MEDIUM.** Real and shipping, but claim versus code gaps on consensus, state channels, PoAI, and identity, plus an upgradeable and permissioned core, keep this out of low risk territory.
