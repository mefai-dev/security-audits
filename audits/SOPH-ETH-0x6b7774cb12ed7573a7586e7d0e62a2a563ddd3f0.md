## Why This Report Exists

Sophon markets itself as a consumer, entertainment, and AI Layer 2, the first ZKsync Validium built on Avail data availability, powered by a decentralized light node and Guardian staking program, with SOPH as the gas and staking token of a live consumer ecosystem. Those are strong claims about decentralization, bespoke engineering, and durable on chain token utility. This report reads the actual public source under github.com/sophon-org and the upstream Matter Labs ZK Stack it forks, reads the live L1 token and L2 chain over public RPC, and reads the L2BEAT project configuration and the team's own announcements, to separate what is confirmed in code from what is inherited boilerplate, from what is marketing. The decisive fact that frames everything below is that on 2026-06-25 the team announced it is winding the chain down.

## Method

Read only, public sources. The Sophon L1 ERC20 was read directly from Ethereum mainnet over public RPC (`ethereum-rpc.publicnode.com`): `name`, `symbol`, `decimals`, `totalSupply`, `owner`, and full runtime bytecode via `eth_getCode`; the owner address was probed for Gnosis Safe `getThreshold`, `getOwners`, and `VERSION`. Verified source was cross read from Blockscout. The Sophon L2 was read over its public RPC (`https://rpc.sophon.xyz`): `eth_chainId`, `eth_blockNumber`, and the base token system contract at `0x...800a`. Token identity and market data were cross checked against CoinGecko. The Avail DA validator and shared bridge contracts were probed for deployed code on L1. Architecture, decentralization, upgradeability, and sequencer facts were read from the L2BEAT project configuration source (`packages/config/src/projects/sophon/sophon.ts` in `github.com/l2beat/l2beat`) and confirmed against the team's decommission announcement and independent reporting.

## The Foundation: a ZKsync Elastic Chain, not a from scratch L2

Sophon is an instance of the Matter Labs ZK Stack, the same codebase that powers ZKsync Era and every other Elastic Chain. Its L1 contracts are a ZKsync Diamond proxy that commits, proves, and executes batches through the shared bridge, and it tracks the shared protocol upgrades (v26 and v29) that Matter Labs ships to every ZK Chain. Sophon's one genuinely distinctive protocol choice is that it runs in Validium mode: instead of posting transaction data to Ethereum, it posts data availability commitments to Avail through a Vector DA bridge and an on chain `AvailL1DAValidator`. Everything else that matters at the protocol level, the prover, the sequencer or operator design, the bridgehub, the account model, is inherited. Sophon's bespoke work lives above the protocol: node and deployment tooling, a Guardian staking program, and account or paymaster UX forked from ZKsync SSO. This foundation matters because most of the claims below are true of the ZK Stack in general, not of Sophon specifically.

## Claim 1: Genuine ZK Stack chain with real validity proofs

CLAIM
> Sophon employs a modular zero-knowledge proof system termed ZK Stack. A ZK powered Layer 2 that processes transactions with validity proofs.

REALITY: CONFIRMED IN CODE, with the clarification that it is a Validium, not a rollup, and the proof system is inherited ZKsync code, not bespoke Sophon cryptography.

EVIDENCE
```
l2beat/l2beat  packages/config/src/projects/sophon/sophon.ts
 L205-208 proveBatchesSharedBridge(uint256 _chainId, ... (uint256[] recursiveAggregationInput, uint256[] serializedProof) _proof)
 L23      const diamond = discovery.getContract('Diamond')      // ZKsync Diamond proxy
 L24      const bridge  = discovery.getContract('L1NativeTokenVault')  // shared ZK Stack bridge
 L21-22   v26UpgradeTS 1743095267 ; v29UpgradeTS 1761612755      // tracks Matter Labs shared upgrades
```
On chain, the operator submits `commitBatchesSharedBridge`, `proveBatchesSharedBridge`, and `executeBatchesSharedBridge` carrying a real recursive aggregation proof. The proving pipeline is the standard ZKsync shared prover (Boojum). Sophon inherits it; it did not build it. The org contains no prover code, and the node Sophon runs generates no proofs:
```

github.com/sophon-org  era-contracts   forked from matter-labs
```
IMPACT: The core cryptographic claim is real. The nuance a reader needs is that this is validity proven Validium security inherited wholesale from Matter Labs, not a differentiator Sophon engineered; a claim that Sophon generates its own proofs would be FALSE.

CLAIM
> Sophon builds its own light nodes and ensures high performance while maintaining complete decentralization and data availability, setting a new standard for modular blockchain design.

REALITY: FALSE as stated. The live system runs a single operator, gates L1 to L2 transactions behind a whitelist, gives users no default way to force a transaction, and keeps data off chain. That is close to the opposite of complete decentralization.

## Centralization Summary

- Sequencer or operator: single operator; `TransactionFilterer` whitelist gates L1 to L2 enqueues; no default force transaction path (sophon.ts L136, L139). Censorship is possible by design.
- Data availability: off chain on Avail via the Vector bridge, `AvailL1DAValidator` on L1, 7 day exit window, DA committee (Validium trust, not rollup DA).
- Upgradeable system contracts: ZKsync Diamond proxy, shared bridge `L1NativeTokenVault`, shared ZK Stack governance and the shared upgrade cadence (v26, v29). L2BEAT: a 4 day 3 hour to 8 day 3 hour delay on code upgrades, except that an EmergencyUpgradeBoard can upgrade with NO delay. Sophon does not unilaterally control its own protocol upgrades; it inherits Matter Labs shared governance. L2BEAT rates the chain Stage 0.
- Account abstraction and relaying are third party, not Sophon built: `mee-node-deployment` wraps Biconomy's MEE node (`bcnmy/mee-node`), `ultra-relay` is ZeroDev's fork of Pimlico's Alto ERC4337 bundler, and the account SDK is a mirror of Matter Labs `zksync-sso`. The one Sophon authored contract, `ContractWhitelistPaymaster.sol`, is a standard ZK Stack paymaster built on `@matterlabs` system interfaces.
- Token owner: L1 SophonToken owner is a Gnosis Safe v1.4.1, 4 of 7 threshold (`0x3b181838ae9db831c17237fabd7c10801dd49fcd`), whose only token level power is a `rescue` helper and ownership transfer. No mint. This is a genuine positive.
- Operational hygiene: public deployment repos commit secrets. `mee-node-deployment/docker-compose.yml` ships the well known Hardhat test key `0xac09...ff80` as `KEY=`, and `sophon-en-config/docker-compose.yml` commits a data availability seed phrase as `EN_DA_SECRETS_SEED_PHRASE`. Both are documented as low value or unfunded, but committing secrets to a public repo is poor practice. The mainnet node also pulls state snapshots anonymously from a Rollup as a Service GCS bucket (`raas-sophon-mainnet-external-node-snapshots`), consistent with a hosted, managed deployment rather than self run infrastructure.

## Positive Findings

- The L1 SOPH token contract is clean and low risk: verified source `SophonToken`, solc 0.8.26, OpenZeppelin `ERC20Permit` plus `Ownable2Step`, NOT a proxy (non upgradeable), fixed supply with no `mint` function, only `burn`, `burnFrom`, and an `onlyOwner rescue` helper. Owner is a 4 of 7 Safe, not an EOA. Read live, `totalSupply` is 9,953,500,000 SOPH, that is the 10 billion genesis minus 46,500,000 burned, and because there is no mint the supply can only fall.
- The Avail Validium integration is real deployed code on L1, not a slide. Sophon was a genuine first mover on ZKsync plus Avail Vector DA.
- Real validity proofs are submitted on L1; the chain is not a trust me sidechain.
- The decommission was communicated honestly, with an orderly migration window and a token buyback and burn plan rather than an abandonment.
- SOPH is a real, liquid, exchange listed asset (Binance, OKX and others), not an illiquid ghost token.

## Conclusion

Sophon is a real ZKsync ZK Stack Validium, and to its credit the two things people most doubt about such projects, real validity proofs and a real, novel Avail DA integration, are both confirmed in deployed code, and the L1 SOPH token contract is genuinely clean. Those positives are why this is not a scam. But of eight tested claims, only two survive as confirmed, four are overstated, and two are false. Almost none of the protocol is bespoke: the core repos are verbatim Matter Labs forks with zero unique commits, the light node is a wrapper around Avail's client plus an off chain rewards monitor, the account stack is third party Biconomy and ZeroDev code, and the flagship 100,000 SOPH Guardian staking contract is not even open source. The live chain is a Stage 0 Validium run by a single operator that can censor users who have no default way to force a transaction, upgradeable with a zero delay emergency path. The decisive fact is that the project itself has concluded the chain is not worth running: on 2026-06-25 the team announced it is decommissioning the L2 after fewer than 200 daily users and about 3.4 million USD per year in costs, is keeping infrastructure alive only through roughly the end of 2026, and is progressively removing the exact SOPH utilities, gas and staking, that the token was sold on. The 500 million USD TVL that was marketed was locked node sale value; real DeFi liquidity peaked near 20 million USD and is now near 160 thousand USD. The wind down is honest and orderly, but a whole project audit cannot score a self retiring, highly centralized, largely forked L2 with collapsing usage as a passing, durable product.

Verdict: Flagged. Score: 42 / 100. Risk: HIGH.
