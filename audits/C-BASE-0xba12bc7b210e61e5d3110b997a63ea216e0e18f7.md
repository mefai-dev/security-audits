Key on chain facts:
- Symbol is `C`, name is `Chainbase Token`, 18 decimals, headline supply 1,000,000,000. The full 1,000,000,000 is minted on Base; the BSC balance (about 58.6M) is the portion bridged out via LayerZero.
- The BSC contract returns `endpoint()` = `0x1a44076050125825900e736c501f859c50fe728c`, the canonical LayerZero EndpointV2. This confirms the omnichain claim technically (LayerZero V2 OFT).
- The Base home contract exposes `mint(address,uint256)` (selector `40c10f19` present in deployed bytecode) and is `Ownable` (owner `0x75286d8aa0a1cf1b966d75adaf5183b562b5a611`). The token is `ERC20Capped`, so a `cap()` does exist in the bytecode, but it is set to 210,000,000,000 C, which is 210 times the marketed and circulating 1,000,000,000 supply; there is no `pause()`. The BSC OFT owner is `0xb0081ffe5e53df121d79d7de503f87d3b0546412`. So the 1,000,000,000 figure the market treats as the supply is a policy number, not a mint cap enforced anywhere near it: the code level cap sits at 210 times the current supply, giving the owner headroom to mint up to 210,000,000,000 C.
- Neither the Base nor BSC token is a proxy (EIP 1967 implementation slot reads zero on both). The token itself is not upgradeable.

Impostor warning (safety finding): two Ethereum L1 contracts surface in searches and explorers as "Chainbase" but neither is the real C. `0x1C89298d7a6A838256b0710e9968005B423dC4a4` returns name and symbol both "Chainbase" with a 1,000,000,000 supply at 9 decimals; `0xD9E0Bb2DbD31089920e3Ab3819a659782D48e05e` returns symbol "$C" with a 1,000,000,000,000 (one trillion) supply at 9 decimals and non standard transfer selectors. Neither returns symbol `C` or name `Chainbase Token`. CoinGecko and CoinMarketCap list only Base and BNB Chain for C. Treat any Ethereum L1 "Chainbase" ERC20 as unverified until Chainbase publishes an official Ethereum OFT address.

## Why This Report Exists

Chainbase markets itself as "the world's largest omnichain data network for AI," an "on chain intelligent operating system" built on a "dual chain," "dual staking," "four-layer" architecture with a self developed "Chainbase Virtual Machine (CVM)." Those phrases describe a decentralized, verifiable, trust minimized data network. In practice, blockchain data indexing is a hard, resource heavy engineering problem that is almost always solved by a centralized service, and a token plus an EigenLayer AVS is frequently attached to a product that is, at its core, a hosted API. The purpose here is to separate what the public source and on chain state actually prove from what the marketing implies, and to state plainly where the core data pipeline is centralized.

## Method

Read only. Steps taken:
1. Direct JSON RPC reads against Ethereum, Base and BNB Chain public nodes for `name()`, `symbol()`, `decimals()`, `totalSupply()`, `owner()`, `endpoint()`, EIP 1967 implementation and admin storage slots, and raw bytecode selector inspection (`mint`, `burn`, `pause`, AccessControl).
2. Reading the public repositories in github.com/chainbase-labs: `manuscript-core`, `chainbase-avs`, `chainbase-avs-setup`, `chainbase-contract`, `chainbase-oft`, `chainbase-docs`.
3. Cross checking documentation, blog and third party explorers (Basescan, BscScan, CoinGecko, CoinMarketCap) and the EigenLayer AVS deployment addresses published in the `chainbase-avs` README against on chain state.
4. Testing each flagship claim against code and on chain reality, and classifying it CONFIRMED IN CODE, OVERSTATED, or FALSE.

No team, founder, or identity analysis was performed. Nothing was signed or transacted.

## The Foundation: a centralized data platform, an EigenLayer AVS, and a testnet L1

The honest architectural summary is three separate things wearing one narrative:

1. A centralized, production data service. Chainbase runs a hosted blockchain data platform (RPC, Token API, SQL, "Theia" natural language queries) that the marketing credits with "500 billion+ data calls," "15,000+ developers" and "8,000 applications." This is the part that actually serves users today, and it is a Web2 style SaaS behind an API, not an on chain network.
2. A real EigenLayer AVS on Ethereum mainnet. The `chainbase-avs` repository ships genuine Go operator or coordinator code and deployed EigenLayer middleware contracts (ServiceManager, RegistryCoordinator, StakeRegistry, and so on). This is real and live, but it is a restaking security layer, not the data pipeline itself, and its concrete validation and slashing task is not documented in the public repo.
3. A not yet live L1 ("dual chain"). The self developed CVM plus CometBFT consensus chain, the C side of "dual staking," and the reward and staking contracts exist only as testnet deployments (Sepolia and Base Sepolia) behind upgradeable proxies. No public Chainbase mainnet chain or explorer was found.

The "four-layer" and "dual chain" diagrams present these as one operating decentralized network. On chain, only pieces 1 (centralized) and 2 (EigenLayer AVS) are live; piece 3 is testnet.

## Claim 1: Manuscript is a real, decentralized data processing framework

CLAIM: Manuscript is described as "a revolutionary blockchain data streaming framework" and "the language of this data network," letting anyone "access any data through any means, across any service, using any language," with "Monetization" of processed data across a decentralized network.

REALITY: OVERSTATED. The framework is real and non trivial as open source software, but it is an off chain streaming SDK that consumes data from Chainbase's own network, and network deployment is "coming soon." It is Apache Flink plumbing on top of a centralized data source, not a decentralized processing network today.

EVIDENCE:
```
repo: github.com/chainbase-labs/manuscript-core  (Apache-2.0)
languages: Java (~43%), Rust (~33%), Go (~21%); ~496k LOC
directories: /cli, /gui, /flink, /decoders, /examples
README architecture: "Start a default stream processing framework, such as a
Flink cluster. Consume user-defined source data. Process these stream data using
your defined transforms. Sink the processed data to the data source."
docs (manuscript overview): data is consumed from the "Chainbase network";
running "on the Chainbase network" is noted as "coming soon" (local Docker only today)
```
```
Processing runs OFF CHAIN in a local Apache Flink cluster; raw blockchain data
originates from Chainbase's hosted network. There is no on chain verification of
Manuscript output in this repo. Independent status check: repo activity present
through 2026 but core merged-PR cadence stalled after Dec 2024.
```

IMPACT: The open source SDK is genuine and usable, which is a positive. But "decentralized data processing" and "data trade within the network" are aspirational. Today Manuscript is a client SDK whose data trust root is Chainbase's centralized platform. Users who assume trustless, verifiable data are relying on a hosted service.

## Claim 2: Dual staking (LST plus C) is implemented and live on chain

CLAIM: "dual staking method supports both Liquid Staking Token (LST) and our native token," with a "Native Dual Staking model where an oracle ensures fair price conversion of both LST and C into C-Stake units," marketed as solving the proof of stake "death spiral."

REALITY: OVERSTATED. Only the ETH or LST restaking leg is live (through EigenLayer, see Claim 4). The C token staking leg, the oracle conversion into C-Stake units, and reward distribution exist only as testnet contracts behind upgradeable proxies. There is no mainnet dual staking system.

EVIDENCE:
```
repo: github.com/chainbase-labs/chainbase-contract  (MIT, work in progress)
contracts: Staking, RewardsDistributor, ZoneFactory, StableCoin/Balance/Transfer Zones
deployments: Sepolia and Base Sepolia TESTNET only (proxy + implementation)
proxy: OpenZeppelin "Transparent Upgradeable Proxy v4.9.6" (upgradeable, admin controlled)
```
```
No mainnet dual staking contract, no live C-Stake oracle, and no C staking address
were found on any production chain. The "C" leg of dual staking is testnet.
```

IMPACT: The economic security story that distinguishes Chainbase from a plain restaking AVS (native C plus LST, C-Stake units, anti death spiral) is not yet real on mainnet. Buyers pricing in a live dual staking economy are pricing a roadmap.

## Claim 3: Dual chain (CVM plus CometBFT) network is live and secures the data pipeline

CLAIM: An "innovative dual chain architecture of both Eigenlayer and Cosmos," using "ABCI++" to translate "the Chainbase Virtual Machine (CVM) state into a format compatible with the CometBFT consensus engine," with a distributed data lake and Arweave storage refreshing in "less than 3 seconds."

REALITY: FALSE as a present tense, live mainnet claim. The Cosmos or CometBFT execution and consensus chain (the CVM L1) is not live on mainnet. Public sources describe the testnet as partially complete with mainnet "expected." No Chainbase L1 mainnet, block explorer, validator set, or genesis was found.

EVIDENCE:
```
docs/blog: "Consensus Layer uses Cosmos' CometBFT"; CVM is "self-developed";
mainnet described as "soon-to-be-launched testnet" / "expected to be launched."
No mainnet chain-id, RPC, or explorer is published. chainbase-contract L1 pieces
(Staking, Zones, L1StandardBridge) are deployed to Sepolia / Base Sepolia only.
```

IMPACT: The "dual chain" pillar, the CVM, and the second consensus leg do not exist as a live decentralized network. Any statement or diagram implying the Chainbase chain is operating and securing data today does not match on chain reality. This is the largest gap between narrative and code.

The caveat: the specific work operators validate, and whether meaningful slashing is enforced, is not documented in the public repo, and the coordinator or aggregator is a Chainbase run component.

## Claim 5: The "hyperdata" pipeline is a decentralized on chain network

CLAIM: "the world's largest omnichain data network," an "on chain intelligent operating system designed to convert decentralized, fragmented on chain data into structured, verifiable, and composable AI-ready data."

REALITY: OVERSTATED. The data indexing and serving that users actually consume is a centralized hosted service (Web2 API plus SQL plus Theia), with an EigenLayer AVS and an open source SDK around it. The verifiable, decentralized, on chain network is the destination, not the current state. This is the core transparency finding.

EVIDENCE:
```
- Manuscript (Claim 1): off chain Flink SDK; data source is Chainbase's own network;
  on-network deployment "coming soon."
- Chainbase L1 / CVM (Claim 3): testnet only, no mainnet.
- Dual staking C leg (Claim 2): testnet only.
- Live pieces that serve data: platform.chainbase.com hosted API + docs.chainbase.com
  (centralized SaaS). Usage figures ("500B+ data calls", "8,000 apps") describe the
  hosted platform, not an on chain network.
- Only live on chain, decentralized component: the EigenLayer AVS (Claim 4),
  which is a security layer, not the indexing pipeline.
```
```
Plain statement: the core data indexing is a centralized service with a token and a
restaking AVS attached. The "decentralized on chain data network" is not yet the
mechanism that produces or verifies the data users query.
```

IMPACT: This is the material disclosure gap. It is not fraud, the product is real and widely used, but the on chain, verifiable, decentralized framing overstates what exists. Data correctness today depends on trusting Chainbase's servers.

## Claim 6: C has a fixed 1,000,000,000 supply and a single canonical token

CLAIM: Aggregators and tokenomics present a 1,000,000,000 max supply single token used for query fees, staking and governance.

REALITY: OVERSTATED on two points. First, the home token on Base exposes a `mint` function and is `Ownable`, and although it is `ERC20Capped` the code level cap is 210,000,000,000 C, which is 210 times the circulating supply, so the marketed 1,000,000,000 is a policy number, not a hard cap enforced anywhere near it. Second, there is no single canonical contract: C is a LayerZero omnichain token on Base and BNB Chain, and there are impostor "Chainbase" tokens on Ethereum L1 that are not the real asset.

## Positive Findings

- The C token is real, listed on Binance and other venues, and tradeable, with a coherent LayerZero V2 OFT design (verified `endpoint()` on BSC). The token contracts are not upgradeable proxies.
- The EigenLayer AVS is genuine and live on Ethereum mainnet: real Go operator and coordinator code, real deployed middleware wired to the canonical EigenLayer AVSDirectory, with a published SlowMist audit. This is meaningfully more than a whitepaper.
- Manuscript is substantial, functional open source software (Apache 2.0, roughly 496k lines across Java, Rust and Go) with a working local Flink pipeline, CLI and GUI. The SDK does what an ETL and streaming tool should do.
- The hosted data platform is a real, revenue relevant product with genuine developer usage, not vaporware.
- Reasonable transparency at the contract level: AVS addresses are published in the repo, contracts are verified on explorers, and the token supply reads cleanly on chain.

## Conclusion

Chainbase is a legitimate, operating project with a real product, real open source code, a genuine EigenLayer AVS, and a real, exchange listed token. It is not a scam. The gap is between the marketing and the mechanism: the flagship "decentralized on chain hyperdata network," the "dual chain" CVM plus CometBFT L1, and the native C "dual staking" economy are largely aspirational or testnet, while the data pipeline that actually serves users is a centralized hosted service. The one clearly false present tense claim is that the dual chain network is live and securing data, since no Chainbase mainnet exists. Centralization is material: upgradeable, single owner AVS middleware; a Chainbase run coordinator; upgradeable testnet staking contracts; a mintable, owner controlled home token; and a closed core indexing service. Add the Ethereum impostor tokens as an end user hazard.

Net: a real company and a real token whose decentralization narrative runs well ahead of its on chain implementation. Passing on product and token reality, flagged on transparency and centralization, and priced for a network that is not yet live.
